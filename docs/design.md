# 設計書

- この文書はKei Agentの設計をまとめた文書
- 使い方は [`using.md`](using.md)、
エージェントを増やすときの決まりは [`agents.md`](agents.md)を参照

## 1. 全体の構成

![Kei Agent の構成](architecture.png)

- オーケストレータは Slack の受け口、権限と接続先、Notion、決まった時刻の処理を持ち、
エージェントは頼まれた仕事だけをして返す構成
- 柵と鍵が1か所に残すことで、エージェントが増えても「誰が何に触れるか」を1つのファイルで管理可能

| 役割 | 場所 |
|---|---|
| 頼む | 個人の Slack ワークスペース |
| 振り分ける・柵を持つ | Kei Agent 本体（オーケストレーター） |
| 実行する | 研究・大学・仕事の3エージェント（同じ Mac の別プロセス、A2A） |
| ファイルを置く | `~/research/` |
| 知見を残す | Notion |
| 声で相談する | Codex App（ChatGPT Voice） |

## 2. Slack

| 項目 | 決めたこと | 理由 |
|---|---|---|
| ワークスペース | 個人用を新しく作る | Bot を自由に入れられ、権限の申請が要らない |
| チャンネル | 先頭に番号を付ける（0番台は全体、10番台は研究テーマ、20番台は大学、30番台は仕事）。フォルダ名と Notion のテーマ名は番号を外したもの | サイドバーの並びを用途の順に固定できる。番号を付け替えても、フォルダや Notion の行は同じものを指し続ける |
| 受け取り方 | Socket Mode | 反応が早く、公開 URL が要らないので Mac の中でも動く |
| 反応する条件 | スレッドの外ではメンションが必要。Bot が動いているスレッド内では、メンションなしで続けられる | メモを書いても反応しない。スレッド内の議論は自然に続けられる |
| 経過の返し方 | 返事は `chat.startStream` で流し、出すのは最後のまとめだけ。いま何をしているかは `assistant.threads.setStatus` で入力欄の下の1行に出す。スレッドの状態は `agents.sessions.setStatus` で processing → active / suspended | 作業の手順を返事の中に1行ずつ並べると、長い作業ほどメッセージが伸びて、結論を読むのにスクロールが要る。経過は消えてよいものなので、入力欄の下だけに出す |
| 答えた印 | 👀 → ✅（エラーが出たら ⚠️） | どの依頼に答えたかが、スレッドを開かなくても分かる |
| 同時に来た依頼 | 違うスレッドは最大2件まで並行。同じスレッドの中は順番。同じテーマで重なったら「別のスレッドの図が混ざっているかもしれない」と添える | 文献調査と分析を同時に頼んでも待たされない。`outputs/` はテーマで共通で、時刻では自分の図と隣の図を区別できない |
| 長いスレッド | ひと段落したとき（Claude が `🧵 区切り: 題` と書く）か、依頼が8回たまったときに [新しいスレッドで続ける] を出す。押すと引き継ぎメモ（目的・決まったこと・分かったこと・次にやること）を書かせて新しいスレッドを立てる | 1つのスレッドにデータの準備から実験までが積み重なると読み返せない（`#amr-query` で1スレッドが5時間・30往復になった）。会話をそのまま持ち越すと軽くならないので、メモだけを渡す。移るかは依頼者が決める |
| 指示できる人 | 自分の Slack ユーザー ID だけ（`KEI_AGENT_ALLOWED_USER_ID`） | 安全のため |

- 外から来た文字（カレンダーの件名、Moodle の課題名など）は、Slack に出す前に `<` `>` `&` を逃がす（`slack_text.escape`）
- 逃がさないと `<!channel>` のような文字列がメンションとして解釈される

## 3. Bot の土台

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 言語 | Python（uv）+ Slack Bolt for Python | 研究のスクリプトと同じ言語でそろう |
| 実行エンジン | Claude Code CLI（`claude -p`）。サブスクリプションで動かす | 今の skill や設定をそのまま使える |
| スレッドと会話 | 1スレッド = 1セッション（`--resume`）。セッションが失われたら、スレッドの履歴をプロンプトに入れて新しいセッションで復元する（200件ずつ読み、新しいほうから600件まで。落とした分は件数を書いて渡す） | ふだんは文脈がそのまま残り、サーバーを移したときも止まらない |
| 途中で止まった依頼 | claude に渡している間は「処理中」の控えを残し、起動時に残っていたものを「入れ替えで止まった」と断ってやり直す | 入れ替えや強制終了のたびに、動いていた作業が黙って消えて 👀 だけが残っていた |
| 動かす場所 | 自分の Mac。`launchd` に登録し、ログイン時に起動して落ちたら再起動する | 開発中は手元の方が直しやすい。Mac mini に移すときも同じ設定を使える |
| 秘密情報 | `~/.config/zsh/local/kei-agent*.zsh`。起動用のシェルスクリプトが読み込んでから起動する | `launchd` からは `~/.zshrc` が読まれない |
| 契約の上限 | `claude -p` が `Claude AI usage limit reached|<エポック秒>` を返したら、その依頼を「明けてからやり直すもの」として覚え、明ける時刻をスレッドに書く。返ってきた時刻が過去のときは30分待つ | 上限は必ず来る。人が気づいて頼み直すまで止まるのを避ける |
| 名前 | Kei Agent。声では「Kei」、自分のことは「僕」 | Keitaroの名前から |

## 4. テーマと作業用ディレクトリ

1テーマ = 1チャンネル = 1ディレクトリ = Notion の1行。これを崩さない。

```
~/research/
├── _overview/            # 研究全体・中長期の方針のチャンネルが書く場所
└── <テーマ>/
    ├── CLAUDE.md         # テーマの前提、研究分野、検索キーワード、ジョブにする基準
    ├── inputs/           # 依頼に添付されたファイル
    ├── outputs/          # 図や集計結果。新しくできたものをスレッドに添付する
    ├── logs/             # ジョブのログ
    └── papers/           # 文献調査で見つけた論文のメタデータと要約
```

- チャンネルに招待すると、ディレクトリと `CLAUDE.md` のひな形ができる。招待のイベントを取りこぼしても、
  最初の依頼のときに作り直す
- 研究全体と中長期の方針のチャンネルは、すべてのテーマを読むだけ。書き込みは `_overview/` のみ
- 研究分野は Bot の設定では決めず、テーマごとの `CLAUDE.md` に書く

## 5. 処理の流れ

### 新しい依頼

1. スレッドの外でメンションされたメッセージを受け取り、依頼者かを確認する
2. チャンネルからテーマと作業用ディレクトリを決定する。メッセージに添付されたファイルは `inputs/` に保存する
3. 👀 を付け、スレッドの状態を `processing` にする
4. 授業・仕事のチャンネルは、そのエージェントへ。研究全体のチャンネルは、軽いモデルで相手と仕事を選ぶ
5. 研究テーマのチャンネルは、そのディレクトリで `claude -p --output-format stream-json` を動かす
6. 流れてくる道具の名前と返答の断片を、入力欄の下の1行に出す
7. 終わったら結果を返信し、`outputs/` の新しいファイルを添付する

### スレッド内の返信

- 保存したセッション ID で `--resume`
- 処理中なら終わってから順番に

### ジョブ

- Claude が skill から `submit` を呼ぶ
毎分 `pueue status --json` を見て、終わったらセッションを再開して「ジョブ X が終わった、出力はここ」と伝える

## 6. 柵

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 許す操作 | 作業用ディレクトリの中の読み書き、Bash、Web 検索、Web ページの取得。Claude Code の sandbox を有効にする | 確認なしに動かすので、書き込みをテーマのディレクトリに閉じ込める |
| 読ませない場所 | sandbox は既定で PC 全体を読めるので、秘密情報と鍵の置き場所を `denyRead` で塞ぐ（`[sandbox] deny_read`） | 読み取りは全部は閉じられないため、トークンと鍵だけを確実に塞ぐ |
| 接続先 | 基本の接続先は `config.toml`。テーマごとの追加は Slack から1つずつ許可する | どのドメインが要るかは動かすまで分からない。昔の実験で開けた穴が残り続けないよう、チャンネルをアーカイブすると消える |
| ジョブの制限 | `submit` はテーマのディレクトリの中にあるスクリプトだけ。作業ディレクトリもテーマに固定する | `pueue` のジョブは sandbox の外で自分の権限のまま動く。スクリプトの中身までは縛れないと理解したうえで使う |
| ジョブの成否 | 投入時に `--expect` で「できるはずのファイル」を宣言させ、終わったら有無と中身が空でないかを確かめる | 終了コードが 0 でも中身は失敗していることがある |
| Claude に渡さないもの | Notion のトークン、GitHub の鍵、`~/.ssh` | 本体が API で取ってきて、ファイルにして渡す |
| 柵そのもの | `src/kei_agent/guard.py`、`config.toml`、`deploy/` は Kei Agent 自身に直させない | Slack のアカウントが1つ乗っ取られただけで柵が外れるのを避ける |

## 7. 定期実行処理

- 本体にスケジューラを組み込み、時刻は `config.toml`で管理する
- App Home から変更可能
- Mac のスリープで逃した処理は、3時間以内なら起きたときに実行する
- `sudo pmset repeat wakeorpoweron MTWRFSU 01:25:00` で毎晩 Mac を起こす（専用機に移すまでのつなぎ）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| Daily | 前日のスレッドと結果、夜間のジョブと Task、先行研究の新着、今日考えるとよい問い、止まっているテーマ。先頭に今日の予定（授業・会議・締切）を**時刻の早い順に1本**で並べ、その上に1日の形を表す帯と、まとまった空き時間を出す。1画面に収め、`_overview/daily/<日付>.md` にも保存する | Codex に渡してそのまま議論を始められる形にする。研究・授業・仕事で3通に分けると、どれも読み飛ばす |
| 1日の帯 | スマホでも崩れないよう、**1行だけ**にして行をまたぐ桁合わせをせず、中身は ASCII（`#` 埋まっている・`!` 締切・`.` 空き）だけにする。空き時間は長い順に選んでから、時刻の順に並べ直す | `▓` や `█` は幅の扱いがフォントで割れる。行をまたぐ図は、画面が狭いと折り返して崩れる。空きを時刻順に並べると、一番長い切れ間が「ほか1か所」に隠れる |
| 振り返り（集め方） | 材料に「大学」（今日が期限だったもの、残っている締切、明日の授業）と「仕事」（今日あった会議、明日の会議）を足す。集めるのは振り返りのときだけ | 朝は、朝のまとめですでに同じことを聞いている。仕事の予定は1回聞くごとに claude が動く |
| 振り返り（見せ方） | 研究・大学・仕事を同じ形で並べる。1領域につき `✅` 今日片付いたこと、`⏳` 途中のもの、`→ 明日:` 明日あるもの。そのあとに、3領域を見たうえでの問いを2つ | 領域ごとにばらばらの形にすると、どこを見ればよいか毎日探すことになる |
| 先行研究 | テーマの `CLAUDE.md` の検索キーワードで arXiv の新着を探し、`papers/` にない論文だけを報告する。新着がなければ投稿せず、Daily で触れる | 何を見張っているかが明確になる。何もない日の投稿でチャンネルを埋めない |
| 停滞 | 一度でも依頼のあったテーマのうち、3日以上動きのないものを Daily で触れる。失敗したジョブや確認待ちが24時間放置されたら、そのスレッドで一度だけ声をかける。そのあとさらに放置されたら、保守で返事待ちを閉じる | 思い出すのは Daily で十分。閉じないと App Home の「いま動いているもの」に何日も居座る |
| 夜間の Task | Notion の「今夜やる」の Task を 01:30 から1件ずつ、一晩5件まで。テーマがない Task は実行せず「確認待ち」にする | 夜にやることが1か所にまとまる |
| 振り返り | 21:00 に材料を `_overview/reviews/<日付>.md` と Slack に用意する。振り返りそのものは Codex で（音声で）行い、結論を貼ると翌朝の Daily に反映する | 音声で議論するという最終目標に合わせる |
| つながらないとき | 朝の定期処理は1回だけ静かにやり直す。相手が落ちていたら `#00_kei-agent` に知らせる | 通知が1回飛ばないより、毎朝黙って失敗し続けるほうが困る |

## 8. Notion

構成は [`notion-layout.md`](notion-layout.md)。

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 置き場所 | Task の正は Notion。論文は `papers/`、テーマの前提は `CLAUDE.md`。Daily と振り返りは Notion のノートにもページを作り、ファイルも残す | 状態や期日を見渡せるのは Notion。Kei Agent と Codex が読むものはファイルのまま |
| 🌙 | Slack で 🌙 を付けると Notion に Task ができる。外すと「未着手」に戻す | Notion で直接「今夜やる」にした Task も同じ流れで動く |
| Claude と Notion | 研究の Claude には Notion を触らせない。本体が API で取ってきてファイルにして渡す | sandbox の方針（通信先を絞る、トークンを渡さない）を保つ |
| 授業の Notion | 別のコネクトを作り、「授業」「課題」の2つだけを共有する | 研究のデータベースと事故で混ざらない |
| ビュー | 並び替え・絞り込み・列の順番は公開 API で作れないので、Claude の Notion 連携から整えてある | 作ったばかりのデータベースは英語の `Default view` に全列が作成順で並ぶ。作り直したらそこも直す |

## 9. Slack から変更できる設定

- 実験のたびに Mac のコードや `config.toml` を直さずに済ませるため

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 変更できるもの | テーマごとの接続先と、決まった時刻の処理の時刻・オン/オフ | 実験のたびに変わるのは接続先。時刻もたまに変えたくなる |
| 変更できないもの | 同時に動かす数、上限時間、書き込み先、読ませない場所、基本の接続先 | 柵そのもの |
| 接続先を足すきっかけ | Claude がつながらなかったとき、返事の最後に `🔒 接続: <ドメイン>（理由）` と書く。本体がそれをボタンにしてスレッドに出す | どのドメインが要るかは動かすまで分からない |
| 許可の単位と範囲 | ドメイン1つずつ、名前ぴったり。テーマごとで、チャンネルをアーカイブすると消える | 理由を見て1つずつ判断できる |
| 押したあと | 許可でも断りでも伝えて、スレッドの作業を自動で再開する | 押したのに何も起きない、を避ける |
| 効くタイミング | 接続先は次の実行から、時刻はすぐ（毎分 SQLite を読み直す） | コードを直さずに済む、という狙いを半分にしない |
| 保存先 | 本体の SQLite。毎晩のバックアップにも入る | テーマのディレクトリは Claude が書けるので、そこに置くと Claude が自分で許可を足せてしまう |

## 10. 自己改善

- 流れは [`using.md`](using.md#自己改善00_kei-agent)、図は [self-improve.png](self-improve.png)

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 直させる範囲 | コード全体。ただし柵に触れた差分は、中身を見る前に捨てる | 柵を自分で外せないようにする。柵を1か所に集めて、それ以外は任せられるようにする |
| 案を考えるとき | リポジトリは読むだけ。書けるのは一時ディレクトリだけ | 案の段階で書き換える必要はない |
| 直すとき | 手元の git worktree で直す。書けるのは worktree の中だけ、通信先は基本の接続先だけ | 取り込むまで、動いている Kei Agent に何も起きない |
| 「いいよ」の判定 | 意味を読むのは Claude。返事の最後に `🛠 着手` か `📦 取り込み` を書く。本体は、その行が**依頼者の投稿で始まった回**の返事にあるときだけ動く | だまされた Claude が行を書いても、依頼者が投稿していない回なら何も起きない |
| 取り込み前 | 変えたファイル、差分（添付）、sandbox の中で回したテストの結果を出す。依存の追加は先頭に出す | 方針ではなくコードを見て決める |
| 取り込むとき | 手元に未コミットの変更があれば止める。main が先に進んでいたら worktree 側で合わせ直す。本体がテストと `ruff`、柵・鍵・大きなファイルを確かめてから早送りで取り込み、push する | 人の書きかけを上書きしない |
| 再起動 | 動いている作業がなくなるのを待ってから自分で終了する（launchd が起動し直す） | 作業の途中で止めない |
| 起動しなかったら | `update-pending` を残し、つながらないまま3回起動し直したら `deploy/run.sh` が `git revert` して前の版で起動し、Slack で知らせる | 止まった Kei Agent には、Slack から直してもらうことも頼めない |
| 同時に直す数 | 1つずつ | 取り込みと再起動がぶつからない |

## 11. エージェントを増やす（A2A）

- 決定事項や詳細な内容は [`agents.md`](agents.md)を参照
- ここには設計理由のみを書く

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 役割の分け方 | 本体がオーケストレーター。エージェントは頼まれた仕事だけをして返す | 柵と鍵が1か所に残る |
| LLM の持ち方 | **エージェントごとに自分の claude を持つ**。ただし依頼者への約束（上限で待つ・やり直す）と、どのエージェントに振るかの判定はオーケストレータが行う。 | ドメインの知識はそのエージェントに閉じたほうが速い。いっぽう契約の枠は1つなので、枠の使い方を分散させると二重にやり直すことになるため。 |
| 振り分け | 名刺からスキルの一覧を作り、軽いモデル（Haiku）に選ばせる。選べなければそのドメインの `ask` に回す | エージェントが増えても振り分けのコードを変えなくてよい。キーワードでは「先週どのくらい進んだ？」を取りこぼす |
| 版と使う機能 | A2A v1.0。`/.well-known/agent-card.json` に名刺、JSON-RPC で `SendMessage` / `GetTask`、`A2A-Version: 1.0` のヘッダ。数秒で終わる仕事はそのまま待ち、数分かかる仕事は `SendStreamingMessage`（SSE）で経過を受け取る | `SendMessage` は相手が終わるまで返ってこないので、長い仕事では途中の様子が出せない |
| 実装 | サーバー側は公式の `a2a-sdk`（土台は `src/kei_agent_a2a/server.py`）。クライアントは aiohttp で薄く自前（`src/kei_agent/a2a.py`） | 仕様の追従は SDK に任せる。本体に FastAPI などを持ち込まない |
| 置き場所と合言葉 | 同じ Mac の別プロセス（launchd、`127.0.0.1` のみ）。共有の Bearer トークン（`KEI_AGENT_A2A_TOKEN`）。名刺は誰でも読めるが、仕事を頼むには合言葉が要る | 外に出さないので、証明書や利用者の管理を持ち込まなくてよい |
| つながらないとき | つなぐ前に断られたなら、3秒待って1回だけやり直す | エージェントを入れ直すと数秒つながらない。そのたびに依頼者へ失敗を見せない |

### 大学エージェント（`src/kei_agent_course/`）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| Moodle | カレンダーの書き出し（ics、`authtoken` 付きでログイン不要）を読む。URL は依頼者が作り `MOODLE_ICS_URL` に置く。パスワードは保存しない | ウェブサービスのトークン発行画面が無効だった。ics なら読み取りだけで、作り直せば失効させられる |
| 取り込む範囲 | 「授業」に入れた履修科目の締切だけ。それ以外は入れず、科目名だけを返事に出す | Moodle のカレンダーには履修していない科目の締切も並ぶ。全部入れると「課題」が読めなくなる |
| Box と Notion（読むぶん） | **Claude のアカウントに付いている連携**を、読む道具だけに絞って使う（2026-09-20 に自前の OAuth アプリから乗り換えた）。ローカルに落とさない。手書きの過去問は `get_preview_page` で画像として見る | すでに繋がっているものを使えば、アプリの登録も鍵の保管も要らない |
| Notion（書くぶん） | Moodle からの取り込みは Python 側の自前トークン。依頼者が頼んだ1件の直し（「提出済みにして」）は、claude が連携で直す | 定期処理は毎回モデルを通したくない。いっぽう1件の直しを本体に集めると、頼むたびに往復が増える |
| 連携の届く範囲 | claude の連携はアカウント全体に届くので、道具では授業ホームに絞れない。触ってよい範囲は `prompts/course.md` で縛り、移動・複製・削除の道具は名指しで断る | Notion のコネクタに、ページ単位の絞り込みがない。消せない・動かせないようにしておけば、間違えても取り返せる |
| Toggl | 読むだけ。プロジェクト＝科目、エントリの説明＝課題名で突き合わせる | 自動で開始すると、止め忘れが実績を汚す |
| 見せ方の分担 | `list-due` は JSON で返し、朝のまとめ・24時間前の知らせ・スレッドへの返事の3つの形は本体が作る | 同じ中身を3か所で違う形に出すので、文の組み立ては1か所だけ |
| やらないこと | 課題の提出の代行 | 取り返しがつかない |

### 研究エージェント（`src/kei_agent_research/`）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 持つもの | `claude -p` の1回分（`run-claude`）と、pueue の待ち行列 | 「1回分の実行」だけを任せると口が1つで済み、別の機械に移しても同じ形で呼べる |
| 持たないもの | 会話の続け方、Slack への見せ方、Notion、引き継ぎの判断、「どのスレッドのジョブか」 | 本体が Slack とスレッドの状態を持っている。両方に分かれると、どちらが正しいか分からなくなる |
| 柵 | 同じ `config.toml` を読む。sandbox、読ませない場所、許可した接続先は本体から渡す | 柵の決め方が2か所に分かれない |
| 移さなかったもの | Kei Agent 自身を直す実行（`self_fix.py`）は本体に残す | 研究エージェントを別の機械に移したときに worktree が無くなる |

### 仕事エージェント（`src/kei_agent_work/`）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| つなぎ方 | 会社の Claude アカウントに付いている Microsoft 365 の連携を、読む道具だけに絞って使う | 会社の IT が Anthropic のアプリに読み取りを許可しているので、Entra ID にアプリを登録しなくてよい |
| アカウントの分け方 | 連携はログイン（プロファイル）に付いてくるので、`CLAUDE_CONFIG_DIR` で専用プロファイルを持つ（大学＝個人、仕事＝会社）。`claude setup-token` の長期トークンでは連携が使えない | 端末のログインを切り替えても、エージェントの動きが変わらない |
| Slack に出すもの | メールや Teams の本文、資料の中身もそのまま出してよい。気にするのは秘密ではなく長さで、長いものは要点をまとめ、判断に関わるところだけを引く | この Slack は依頼者ひとりのもので、ほかに見る人がいない。仕事のスレッドはディスクにも残らない（作業用ディレクトリを持たないので、スレッドのログを書かない）。読みにくさだけが残る問題 |
| やらないこと | 送信、予定の作成・更新・削除 | 会社の相手に取り返しのつかないことをしない |

## 12. 声のレイヤ（`src/kei_agent_voice/`）

- 現時点では第0段階（ハードなし、追加のお金なし）まで実装済み
- アーキテクチャは [voice.svg](voice.svg)
- **Stack-chan を口にする作り直しの設計は [`voice.md`](voice.md)**（2026-09-21 に決めた。まだ作っていない）。
  下の表は、いま動いている第0段階の決めごと

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 役割の分け方 | 相談は Codex（声）、作業は Claude（Slack）。人格はどちらも Kei Agent | 契約の枠が分かれる。声で長く話しても、Slack の Kei Agent が止まらない |
| 入出力 | 入力は Aqua Voice、出力は VOICEVOX（四国めたん、1.2 倍）。文ができた端から鳴らし、Enter で止められる | 全文を待つと最初の一言までが長い。入力側はすでに解決している |
| 目印 | Codex に `📌 決定:` / `🛠 依頼:` / `🎯 テーマ:` を書かせ、声のレイヤは行を見るだけ | Slack 側（`🛠 着手` など）と同じやり方。言い回しの揺れで誤爆しない |
| 依頼を渡す前 | 「`#10_amr-query` に『〜』と頼むよ。いい？」と読み上げ、返事をもらってから渡す | 文字起こしは必ず誤る。動き出してからでは戻せない |
| 依頼の渡し方 | `<state_dir>/asks/` にファイルを置き、本体が数秒ごとに拾ってスレッドを立てる（`kei-agent-ask`） | Slack の鍵を増やさない。Bot の投稿では Kei Agent が反応しない |
| 記録 | 全文は `_overview/voice/<日付>.md`（30日で消える）。決まったことだけ Slack | 読み返さない記録を増やさない |
| 置き場所 | 本体とは別のパッケージ。本体に足すのは依頼の受け口だけ | 試作をやめるときに消しやすい |

## 13. 時間の記録

- 「自分が寝ている間にどれだけ進んだか」を見るために、人の時間と Kei Agent の稼働を並べる
- 材料は週ごとの CSV（`_overview/time/<月曜>.csv`）まで Kei Agent が用意し、**グラフは Claude が作る**（Kei Agent に描画のライブラリを持ち込まない）

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 人の時間 | Toggl（2.0）で自分で測る。プロジェクト名の先頭に `研究/`・`大学/`・`仕事/` の印を付け、**印のあるものだけ**を数える | 科目やテーマが増えても、こちらのコードを変えなくてよい。印のないもの（アルバイト、個人開発）は自然に落ちる |
| 何を測るか | 人がそこに注意を向けている時間。自分で手を動かすときも、Claude に指示して結果を確かめるときも測る。任せて別のことをしている間は測らない | 任せている間は `runs` が数える。2本の線が重ならず、自分の時間と任せた時間をそのまま比べられる |
| 仕事の時間 | 案件ごとに測る（`仕事/ゆうちょ` など） | 予定の長さで代用すると、実測と混ざって嘘になる。**顧客名が個人の Toggl に残る**ことは承知のうえで選んでいる |
| Kei Agent の時間 | `runs` テーブルの実行時間。テーマのチャンネル以外は「そのほか」にまとめる | Kei Agent が動くのは研究だけ。研究全体や改善のチャンネルの分を、テーマの積み上げに混ぜない |
| Toggl の API | Toggl 2.0 の API（`focus.toggl.com/api`）を `toggl_sk_` の鍵で読む。組織とワークスペースの ID は環境変数で渡す | アカウントが 2.0 に移ると、従来の Track の API（v9）は 2.0 の鍵で 401 になる。組織の ID を調べる API はない |

## 15. これからの展望

- **計算先を増やす**（研究室の GPU サーバ、大学の HPC）… 使える機械がまだないので未実装
  増やすときも **Claude から見える形は変えない**（`submit / status / cancel` の3つのまま）。
  ジョブに `--host <名前>` を足し、名前は `config.toml` の `[compute.<名前>]` に書いたものだけにする。
  大きい入力は計算先に置いたままにし、持ち帰るのは `outputs/` とログだけ。
  クラウドの従量課金と Colab は使わない（止め忘れと、無人で走らないため）
- **Mac mini への移設** … ジョブの依頼ファイルと、できたファイルの確認は、まだ本体が直接見ている。
  移すときに A2A のスキルへ移す
- **研究室 Slack の参照** … 管理者の許可が要る
- **声のレイヤの作り直し** … Stack-chan を口にして常駐させる。設計は [`voice.md`](voice.md) に決めてある。
  音声の部品（合成・文字起こし・ウェイクワード）だけ、聴いて測ってから決める
- 決まった時刻の処理を A2A の「タスク」として持たせ直すのは、必要が出てからにする
- Toggl の実績を Notion の「課題」の「実績時間」に書き戻すかは未定
- ics から取れるのは締切と科目名だけなので、課題の本文や提出状況が要るときは、別の入口を考える
- 秋学期の科目は、まだ Moodle のカレンダーに並んでいないため、秋学期が始まったら、締切の言い回しの拾い方を確かめ直す
