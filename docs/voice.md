# 声のレイヤと Stack-chan（設計）

机の上で声で相談し、作業は Slack の Kei Agent がやる、という形の設計。
2026-09-21 の設計の確認（grilling）で決めた。**まだ作っていない。**

いま動いているのは第0段階（`src/kei_agent_voice/`）で、Aqua Voice がターミナルに打った文字を読み、
Codex に相談し、VOICEVOX で読み上げる。これは**作り直す**（Q28）。図 [voice.svg](voice.svg) は第0段階のもの。

仕組み全体は [`design.md`](design.md)、エージェントの決まりは [`agents.md`](agents.md)。

## 1. 何をどこでやるか

| 役割 | どこ | なぜ |
|---|---|---|
| 耳（聞く・ウェイクワード・文字起こし） | **Mac** | 音を無線で運ぶ区間を作らないのが、遅延にいちばん効く。Mac も机の上にいるので距離は同じ。内蔵マイクの質も上 |
| 考える（相談） | **Mac** → Codex | 契約の枠が Slack の Kei Agent と分かれる。声で長く話しても Slack が止まらない |
| 音声合成 | **Mac** | 本体の TTS は中国語・英語向けで、日本語は実質なし。声を選べるのは Mac 側だけ |
| 口（喋る）・顔・首・カメラ | **Stack-chan** | 画面を見ていないときに気づけるのが、机に置く理由 |

**本体（Stack-chan）だけではできないこと**（調べた事実）

- **文字起こし** … whisper tiny がモデル 75MB・実行時 約390MB。PSRAM は 8MB で、50倍足りない。
  語彙を固定すれば ESP-SR の MultiNet で可能だが PSRAM 2.3〜2.9MB を占有し、ESP32-S3 限定
- **日本語の音声合成** … ESP-SR の TTS は中国語・英語向け。日本語は実質 AquesTalk（有償）だけ
- **カメラと音声の同時** … `GC0308` にハードウェア JPEG が無く、圧縮が CPU に乗る。
  I2S の録音・再生・WiFi・推論が同じ MCU に集中し、**最初に壊れるのは音**（I2S の取りこぼし＝音切れ）

**本体でできること**（使っていないものも含む）

- ウェイクワードの常時待ち受け（ESP-SR の AFE＋WakeNet9 で内部RAM 約76KB・PSRAM 約1.06MB・CPU 約20%）。
  **今回は使わない**（耳は Mac）。使うなら内蔵マイクが弱く、外付けマイク U089 が必要
- リップシンク（再生音から本体が自動生成。`m5stack-avatar` の標準機能）
- 顔検出（静的RAM +10KB、Flash +680KB）。顔**認識**と向きの推定は苦しい

## 3. 遅延

声の体験は「最初の一声までの時間」でほぼ決まる。2段構えにする（Q10）。

| 何 | 目標 | どうやって |
|---|---|---|
| 呼びかけへの反応 | すぐ | 合成済みの固定音声を鳴らす（3種類: 呼びかけの反応・考え中・聞き取れなかった） |
| 中身のある返事 | 2秒以内に**喋り始める** | 言い終わるまで待たない。文ができた端から送る |

- 相槌も Mac から送る（`stackchan-atama` に音を貯めて鳴らす口が無い）。LAN で数十 KB なら 100ms 程度
- **Codex の会話は開いたままにする**（Q12）。1往復ごとにプロセスを起こすと、モデルの返事とは別に必ず時間が乗る

### 速い道と遅い道

Kei Agent が**すでに答えを持っているもの**は、モデルを通さない。

| | 速い道 | 遅い道 |
|---|---|---|
| 何に答えるか | 時刻・今日の予定・次の授業・次の会議・締切、Kei Agent の状況（動いているか、ジョブ、上限） | それ以外の相談 |
| 誰が答えるか | 声のレイヤが手元のデータから | Codex |
| 振り分け | **言葉で当てる**（0秒）。外したら遅い道へ | — |

- 振り分けに軽いモデル（Haiku）を置くと、**速い道の全部に往復が乗る**ので使わない。
  取りこぼしても Codex が答えるので、当てが雑でも壊れない
- 手元のデータは、**本体が変わったときに押しておく**（聞かれてから取りに行かない）。
  予定と締切は朝に決まって日中ほとんど変わらない
- 即答したうえで、続きがあれば追いかけて喋る（Codex が `🗣 ひとこと:` を書いたときだけ。毎回2回喋るとうるさい）
- 研究の進捗の要約は遅い道（要約にモデルが要る）

## 4. 本体（オーケストレーター）とのつなぎ方

向きで手段が違う。理由は「待たせたくないか」と「柵を1か所に保つか」。

| 向き | 手段 | なぜ |
|---|---|---|
| 本体 → 声のレイヤ（状態を伝える） | **A2A**。声のレイヤが A2A サーバーになり、本体が投げっぱなしで頼む | 別プロセスから SQLite を読むと、テーブルの形を変えるたび両方直す。返事は待たない（机の上のロボットに Slack を引きずらせない） |
| 声のレイヤ → 本体（依頼を渡す） | **ファイル**（`<state_dir>/asks/`。本体が数秒ごとに拾う） | 本体に受け口を作ると Slack の窓口が2つになり、柵と権限の判定が2か所に散る。依頼は投げっぱなしなので数秒の遅れは体験に出ない |

`docs/agents.md` の規約に全部そろえる。

| もの | 値 |
|---|---|
| エージェント名 | `voice` |
| パッケージ | `src/kei_agent_voice/`（**中身は作り直す**。名前は規約のため保つ） |
| ポート | `8790`（大学 8787、研究 8788、仕事 8789 の次） |
| launchd | `com.kei-agent.voice`（**常駐**。呼びかけを待ち続けるので、コマンドではなくサービス） |
| ログ | `~/Library/Logs/kei-agent/voice-launchd.log` |
| 秘密情報 | `~/.config/zsh/local/kei-agent-voice.zsh`（`STACKCHAN_URL` など） |
| 合言葉 | 既存の `KEI_AGENT_A2A_TOKEN` |

### スキルは `notify` 1つ

本体が渡すのは**出来事だけ**。文・顔・首は声のレイヤが組み立てる（本体に「どんな顔をさせるか」を持たせると、対応表が2か所に散る）。

| `kind` | いつ | 声のレイヤがすること |
|---|---|---|
| `schedule` | 朝のまとめができた | 手元に置く（喋らない） |
| `due` | 締切24時間前 | 喋る＋顔を向ける |
| `working` | 依頼を受け取った（👀） | 顔だけ（**喋らない**。依頼のたびに喋るとうるさい） |
| `done` | 作業が終わった（✅） | 喋る＋顔を向ける |
| `failed` | 止まった（⚠️） | 喋る＋顔を向ける |
| `limited` | 契約の上限に当たった | 喋る＋`sleepy` |
| `awaiting` | 返事待ちになった（❓ 確認） | 喋る＋顔を向ける |

`awaiting` を入れるのは、Slack を見ていないと「Kei Agent が聞き返して止まっている」ことに気づけないから。

### 声で読む文は、声のレイヤが作る

`design.md` には「同じ中身を3か所で違う形に出すので、文の組み立てはオーケストレーター側に1つだけ置く」とある。
**声はその例外にする。** 目で読む形と声はそもそも別物で、帯（`` `9時 .####.##!...` ``）も URL も読めず、
「あと23時間で締切」は声なら「明日の夕方までだよ」の方が自然。同じ文の2つの見せ方ではなく、別の文として作る。

## 5. 顔・首・カメラ

| Kei Agent の状態 | 顔 | 首 |
|---|---|---|
| 誰もいない | `sleepy` | 正面で止める |
| 呼ばれた | `neutral` | **顔の方を向く** |
| 聞き取れなかった | `doubt` | 小さく傾ける |
| 考え中 | `neutral` | わずかに下を向く |
| 依頼が動いている（👀） | `neutral` | ときどき下を向く |
| 終わった（✅） | `happy` | **顔の方を向く** |
| 止まった（⚠️） | `sad` | 顔の方を向く |
| 上限に当たった | `sleepy` | 下を向く |

`angry` は使わない（Kei Agent が怒る場面がない）。肝は **✅ と ⚠️ で顔を向けること**。

### カメラは「追わない」

`/capture` は静止画で、圧縮が CPU に乗り、音と同時にやると音が切れる。だから**連続して顔を追うことはできない**。

- ふだんは **10秒おきに1枚**。喋っている間は撮らない
- 離席は **60秒見えなければ「いない」**
- 首を向けるのは「呼ばれたとき」と「喋り始めるとき」に**1回ずつ**（追従ではない）

狙い（画面を見ていなくても気づける）はこれで満たせる。音が切れる方が体験としてずっと悪い。

### 離席中の知らせ

溜めて、戻ってきたら**1回にまとめる**（「離れている間に3件終わったよ。詳しくは Slack」）。
1件ずつ喋ると、離席が長いほど喋り続けることになる。**1時間以上前のものは、数に入れるだけで読み上げない。**

## 6. 会話と記録

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 相談相手 | Codex（声では「Kei」と名乗る） | 契約の枠を Slack と分ける。声で長く話した日に研究が止まるのを避ける |
| 会話の区切り | 日付が変わったら切る。**長く離席したら切る**（2時間見えなかったら次は新しい会話） | 離席から戻ると話題も変わっている。前の文脈を引きずると的外れになる |
| 記録 | 全文は `<agent_root>/overview/voice/<日付>.md`（30日で消える） | 読み返さない記録を増やさない |
| Slack に残すもの | **なし** | 記録はファイルにあるので足りる（第0段階の `📌 決定:` → Slack はやめる） |

## 7. 出力先

| 状態 | どうなる |
|---|---|
| `STACKCHAN_URL` があって `/status` が返る | Stack-chan が喋る |
| 無い・返らない | **Mac のスピーカーが喋る** |
| App Home の「声で知らせる」を切っている | 本体が `notify` を送らない（＝黙る） |

「黙るかどうか」は本体の判断（送らなければよい）、「Mac か Stack-chan か」は声のレイヤの判断（`/status` で分かる）。
App Home に置くのは**入/切だけ**にする。3択にすると、本体が Stack-chan の生死を知る必要が出てくる。
`config.toml` の柵（同時に動かす数、書き込み先、読ませない場所、基本の接続先）には触らない。

## 8. 誰の声を受け付けるか

**判定しない**（自室で、人が来ない前提）。

そのかわり、**依頼を渡す前に読み上げて確認する**。「`#10_amr-query` に『〜』と頼むよ。いい？」と聞き、
返事をもらってから渡す。文字起こしは必ず誤るので、動き出してからでは戻せない。

Slack は `KEI_AGENT_ALLOWED_USER_ID` で依頼者1人に絞っているが、声の依頼は `asks/` に
ファイルを置く経路で、本体はそのファイルを信じる（書けるのは自分だけ、という前提）。
Stack-chan を机に置くと、この前提は「その部屋にいる人なら誰でも」に変わる。
**人が来る場所に移すときは、ここを決め直す**（読むだけの質問は通し、作業の依頼は Slack だけにする、など）。

## 9. 音声の部品（調べた事実と、推奨）

**まだ決まっていない。** 下は調べた事実と推奨で、実際に聴いて・測って決める。

### 音声合成

いまは VOICEVOX（四国めたん）で、`127.0.0.1:50021` に `/audio_query` → `/synthesis` を叩いている。
不満は「人工合成感」。

| 候補 | 分かったこと |
|---|---|
| **AivisSpeech Engine**（推奨） | VOICEVOX ENGINE から派生していて `/audio_query` → `/synthesis` が共通。**接続先を変えるだけで声を替えられる**。ローカル、無料、Apple Silicon（M1以降）が推奨環境、RAM 1.5GB 以上、GPU 不要。注意: 話者 ID が 0 からの連番でなく変則的な数値（例 `888753760`）。一度に 500 文字程度まで |
| Aivis Cloud API | 上とは**別物**。公称 0.3 秒で喋り始め、ストリーミング対応。ローカルで速度が足りないときの逃げ道。従量課金 |
| COEIROINK / SHAREVOX | 同じく VOICEVOX API 準拠（COEIROINK は v1.x まで。v2 は独自路線で非公式ブリッジが必要） |
| Style-Bert-VITS2 | 感情・スタイルの強弱を明示的に制御できる。コードは AGPL/LGPL だが**モデルは別ライセンス**で個別確認が必要 |
| クラウド（ElevenLabs / OpenAI / Gemini / Azure） | 日本語の自然さに特化した評価が見つからない。ElevenLabs は日本語で text normalization を使うと遅延が大きく増えると API 文書が明記 |

**自然さを定量比較したベンチマークは見つからなかった**（主観記事のみ）。だから**聴き比べて決める**。

### 聴き比べ方（用意してある）

engine の向き先は環境変数で替えられる（`speech.Voicevox.from_env`）。コードは変えない。

```zsh
# 1. VOICEVOX と AivisSpeech の両方を立ち上げる（両方いても構わない。待ち受け口が違う）
# 2. 同じ文を、動いている全部のエンジンで鳴らして wav に落とす
uv run kei-agent-voice-compare
uv run kei-agent-voice-compare --no-play   # 作るだけ（あとで聴く）

# 話者を選びたいとき（AivisSpeech の ID は 0 からの連番ではない）
uv run kei-agent-voice-compare --speakers
uv run kei-agent-voice-compare --speaker 888753760

# 待ち受け口が既定（50021 / 10101）と違うとき
uv run kei-agent-voice-compare --port 12345
```

wav は `<agent_root>/overview/voice/compare/` に残るので、あとから聴き直せる。

決まったら、秘密情報のファイル（`kei-agent-voice.zsh`）に書く。

```zsh
export KEI_AGENT_VOICE_PORT="10101"
export KEI_AGENT_VOICE_SPEAKER="888753760"
```

### 文字起こし

| 候補 | 分かったこと |
|---|---|
| **whisper.cpp（Core ML）**（まずこれ） | Core ML ＋ VAD で約7秒の音声を約1秒という実測報告。Python/CLI から呼びやすい |
| MLX Whisper | M4（32GB）で large-v3（8bit）がリアルタイムの 3.44 倍速、medium で 10 倍速 |
| **Apple の `SpeechTranscriber`**（macOS 26 の新 API） | 日本語を含む約40言語、**完全オンデバイス、モデルのダウンロード不要**、ストリーミング設計、1分制限なし。この Mac は macOS 26.5.2 なので使える。ただし**遅延の実測が情報源で大きく割れている**（約1秒 という報告と、10秒超 という報告）。さらに **Python から呼ぶには Swift の小さな橋が要る** |
| faster-whisper | Apple Silicon では CUDA の恩恵がなく、MLX や whisper.cpp より遅いという報告が複数 |

➡️ **whisper.cpp で作り始め、遅ければ `SpeechTranscriber` に乗り換える。** OS 標準は魅力的だが、
遅延の報告が割れていて、橋を書く手間もかかる。先に動くものを作って、実際の遅延を測ってから決める。

### ウェイクワード

| 候補 | 分かったこと |
|---|---|
| **Picovoice Porcupine**（推奨） | **日本語のカスタムワードを公式にサポート**（Console で日本語を選んで単語を打つ）。macOS SDK あり。**非商用・個人利用は無料**（カスタムワードは月1モデル） |
| openWakeWord | 公式の学習パイプラインが**英語専用**（合成音声の TTS が英語データのみ）。日本語で学習した成功事例が見つからなかった。英語モデルのまま日本語で呼びかけても検出できたという報告はある |
| livekit-wakeword | 30以上の言語に対応し、日本語の学習例あり。誤検知が openWakeWord の 1/100 という開発側の報告。**Apple Silicon 対応の明記が見つからなかった** |

➡️ **Porcupine**。`design.md` の第1段階には openWakeWord と書いてあるが、**日本語では公式に道が無い**ので置き換える。
「ケイ」のような短い語は誤検知しやすいので、呼びかけの言葉は実際に試して決める（長めの方が安定する）。

### 測ってから決めること

1. AivisSpeech と VOICEVOX を同じ文で鳴らして、**自然さと、喋り始めるまでの時間**を比べる
2. whisper.cpp で 3〜5秒の発話を文字にする時間を測る（目標は Q10 の「2秒以内に喋り始める」に収まること）
3. 「ケイ」の誤検知を1日分数える
