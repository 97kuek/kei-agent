# 授業ホーム Notion DB 統一・表示設計

## 目的

既存の授業ホームで、`授業`、`課題`、`学習ログ`、`📊 成績履歴`、`🎓 単位要件`、`📈 GPA推移` を正本として連携する。
既存のページ・DB・プロパティ名・入力済みデータは削除も改名もしない。ただし、`課題` DB のタイトルプロパティだけは、利用者が求めた表示名 `課題` に改める。

## 確認済みの現状

- 正本候補のうち、`学習ログ` だけが不足していたため、作成済み。
- `授業`、`課題`、`📊 成績履歴`、`🎓 単位要件`、`📈 GPA推移` は既に存在し、データも保持している。
- 成績・単位要件・GPA は既存の人間向けプロパティ名を使っており、旧実装が別名の title プロパティを追加しようとして停止した。
- `Untitled` の DB が2件ある。中身も配置も判断せず、今回の移行対象から外す。

## 正本と relation

次の relation を正本とする。

```text
授業 ← 課題
授業 ← 学習ログ
授業 ← 成績履歴
成績履歴 ← 単位要件
成績履歴 ← GPA推移
```

既存の `授業 ← 単位要件` と `授業 ← GPA推移` は消さない。既存データの参照を壊さずに、成績を起点にした不足 relation を追加する。

## スキーマ互換

セットアップと学業記録の同期は、既存のプロパティ名を正として扱う。

| DB | title / 数値プロパティ | relation |
|---|---|---|
| 課題 | `課題`、`締切`、`状態` | `科目` |
| 成績履歴 | `科目名`、`取得年度`、`単位`、`成績`、`GP`、`科目区分` | `授業`、新設する `単位要件`、`GPA推移` |
| 単位要件 | `要件名`、`所定単位`、`既得単位`、`算入単位`、`残り単位` | 新設する `算入成績` |
| GPA推移 | `期間`、`年度`、`種別`、`GPA` | 新設する `対象成績` |

Kei Agent の stable ID プロパティだけは、既存DBに無い場合に追加する。既存の科目・要件・成績ページを推測して relation で結ばない。

## 課題の見せ方

`課題` DB に `課題一覧` table view を作る。表示列は `科目`、`課題`、`締切`、`状態` の順で、その他の運用列は隠す。締切の早い順に並べる。

Moodle の題名が厳密に `「…」の提出期限` に一致するときだけ、`…` を課題名として保存・表示する。その他の Moodle 題名は変えない。既存行も同じ規則で一度だけ整える。

Moodle から新規作成する課題ページは、本文が空のときにだけ次の整理用見出しを持つ。

```text
## やること

## 提出物

## 進捗メモ

## 資料・リンク
```

既存ページの本文は一切書き換えない。

## GPA の見せ方

`📈 GPA推移` に `GPA推移` chart view を作る。年度・期間の昇順を基準にし、横軸を `期間`、縦軸を `GPA` とする。既存の GPA レコードだけを可視化し、値の補完や推測はしない。

## 実施と検証

1. 既存DBのプロパティ名へセットアップ・同期コードを適合させる。
2. unit test で既存 title プロパティへの適合、relation 追加、題名正規化、空ページだけへのテンプレート追加、view payload を確認する。
3. `kei-agent-course-setup` を再実行し、DB重複なし・6DBの state・relation を確認する。
4. Moodle の読み取り専用照合と、課題DB・GPA view の状態を確認する。

失敗時は新規作成済みのDBや relationを削除しない。エラー内容を記録し、次の書込みを止める。
