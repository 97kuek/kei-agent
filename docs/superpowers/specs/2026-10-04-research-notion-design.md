# 研究の Notion の作り直し

## 目的

- Dot に頼んだ研究の作業の今の状態を、テーマのページを開けば追えるようにする
- 研究の DB と列を減らし、どこに何があるかを分かりやすくする
- Dot と Kei Agent が、書き込む先と列の名前で迷わないようにする

## 決めたこと

### 研究ホーム

- 置くのは、テーマの DB、「中長期の方針」のページ、研究室のリンクだけ
- テーマの DB は、Status が In progress のテーマを上に出す
- 「自分の Task」「近いマイルストーン」の表は置かない。テーマをまたいだ一覧は、朝の Daily が受け持つ

### テーマ（DB）

| 列 | 種類 | 中身 |
|---|---|---|
| Name | タイトル | テーマの名前。Slack のチャンネル名の「数字-」より後ろ（作業場の名前）と同じ |
| Status | ステータス | In progress / On hold / Done |
| Start | 日付 | 始めた日 |
| End | 日付 | 終えた日 |
| Duration | 数式 | Start から End までの日数。End が空なら Start から今日まで |

### テーマのページ

上から次の順に置く。見出しと DB の名前は固定し、Dot はこの名前で探す。

1. **前提とキーワード**（見出し）: どんな論文やデータが関係するかの前提と、先行研究を探す検索キーワード。Mac の各テーマの `AGENTS.md` は、ここを写す側にする
2. **進捗ログ**（見出し）: Dot が日付付きで書き足す
   - 何かが進んだとき（そのテーマの Task が終わった、実験やジョブの結果が出た、テーマのチャンネルで方針が決まった）に1〜3行
   - 夜の振り返りのときに、その日に動きがあったテーマにだけ「今日のまとめ」を1件。動きが無いテーマには書かない
3. **Task**（DB）
4. **先行研究**（DB）

計画や議論メモは、テーマのページの下に普通のページとして作る。

### Task（テーマごとの DB）

| 列 | 種類 | 中身 |
|---|---|---|
| Title | タイトル | Task の名前 |
| Status | ステータス | Not started / Tonight / Running / Waiting / Done |
| Owner | 選択 | Me / Kei |
| Due | 日付 | 期日 |
| Work & Result | 文 | 作るときに「作業: …」、実行中は受付番号、終わったら「結果: …」を書き足す |
| Slack | URL | 頼まれたスレッド。結果をそこに返す |

- 夜間の Task は、In progress のテーマを順に開き、Owner が Kei で Status が Tonight の行を拾う
- 夜間の Task は「作業:」の部分を Kei Agent への頼みごとにする

### 先行研究（テーマごとの DB）

| 列 | 種類 | 中身 |
|---|---|---|
| Title | タイトル | 論文の題 |
| Summary | 文 | 2〜3文の要約と、このテーマとの関係1文 |
| Link | URL | 照合キー。arXiv は `abs` の URL にそろえ、バージョン番号（v1・v2）を外して比べる |
| Status | 選択 | Unread / Read / Use |

- 同じ論文が複数のテーマにかかわるときは、それぞれのテーマの先行研究に1行ずつ入れる
- 見つけた日は、Notion のページの作成日時を使う

### なくすもの

- ノート（DB）
- マイルストーン（DB）
- 研究全体で1つだった Task と先行研究（DB）
- 消す列: テーマの目的・Slack・ディレクトリ・最終更新、Task の優先度・作成日・テーマ、先行研究の ID・著者・年・会場・この研究との関係・見つけた日・出どころ・テーマ

## 合わせて直すもの

### Dot

- 定期実行のプロンプト（`docs/prompts/`）
  - 朝の一覧と Daily: In progress のテーマを順に開き、今日が Due の Task、Waiting の Task、3日以内が Due の Task を集める。止まっているテーマは、Status が On hold のもの
  - 夜間の Task: 上の「夜間の Task」の拾い方にする
  - Kei Agent からの知らせ: Status が Running の Task を、テーマを順に開いて探す
  - 振り返り: 今日が Due の Task をテーマを順に開いて集め、進捗ログの「今日のまとめ」を書く
  - 先行研究の新着: テーマのページの「前提とキーワード」を読み、そのテーマの先行研究に Link で照合して書く
- 継続指示（`docs/prompts/dot-custom-instructions.md`）
  - 「今夜やって」: そのテーマの Task に、Title・Status=Tonight・Owner=Kei・Work & Result=「作業: …」・Slack で1行作る
  - 進捗ログを書くときの決まり（上の「進捗ログ」）
  - 新しい研究テーマのチャンネルができたら、テーマの行と、ページの見出し・Task・先行研究を作る

### リポジトリ

- `src/kei_agent/storage/notion.py`: 研究ホームの作り（THEMES・TASKS・NOTES・MILESTONES・PAPERS と Setup）を新しい形にする。テーマのページの中に Task と先行研究の DB を作る処理にする
- `src/kei_agent/storage/notion_store.py`: テーマのページから Task と先行研究の DB を見つける形にする。ノートとマイルストーンを読む処理はなくす
  - `ensure_theme`（新しいテーマの作業場を作るとき、`conversation/assistant.py` から呼ばれる）は、テーマの行とページの中身を作る
  - Mac 側で止めてある夜間の Task と Daily が使う処理（`tonight_tasks`・`tasks_due_on` など）は、新しい形に合わせる
- `src/kei_agent/testing/fakes.py` と `tests/`: 偽物とテストを新しい形に合わせる
- `docs/`: 研究ホームの作りを書いている箇所

## 移し方

1. 各テーマのページに、前提とキーワード・進捗ログの見出しと、Task・先行研究の DB を作る。テーマの DB の列を新しい形にする（Start は今わかる開始日、分からなければ空）
2. 古い Task と先行研究の行を、各行の「テーマ」を見て新しい DB に移す。列は次のように写す
   - Task: タイトル→Title、状態→Status、担当→Owner、期日→Due、本文と結果→Work & Result、Slack→Slack
   - 先行研究: 名前→Title、要点＋この研究との関係→Summary、URL→Link、状態→Status
   - テーマが付いていない行は、移す先をあなたに確認する
3. ノートの中身はテーマのページの下のページに、マイルストーンは Due 付きの Task か予定カレンダーに移す
4. 行の数と中身が古い DB と合っているかを確かめる
5. Dot のプロンプトとリポジトリのコードを新しい形に切り替える
6. あなたに確認してから、古い DB を消す（ゴミ箱に入り、30日間は戻せる）

## 確かめ方

- `uv run python -m pytest` と `uvx ruff check .`
- 切り替えた翌日の朝の Daily・夜間の Task・先行研究の新着で、テーマのページの Task と先行研究が読み書きされていること
- 「今夜やって」で頼んだ Task が、そのテーマの Task に Tonight で入ること

## 今回は扱わないもの
