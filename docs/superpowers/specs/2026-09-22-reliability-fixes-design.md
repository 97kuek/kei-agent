# 信頼性修正の設計

## 目的

レビューで見つかった実運用上の不具合を、既存の責務境界を大きく変えずに修正する。
今回の対象は A2A 認証、Slack 外からの依頼キュー、音声設定と通知、Notion 権限の文書化、
自己改善の説明である。A2A executor の共通化と `Assistant` の分割は別の変更として扱う。

## A2A 認証

- A2A の仕事用 API は `KEI_AGENT_A2A_TOKEN` による Bearer 認証を必須とする。
- `/.well-known/agent-card.json`、`/.well-known/agent.json`、`/health` は従来どおり認証不要とする。
- サーバー起動時にトークンが空なら、警告して無認証で続けず、理由が分かるエラーで停止する。
- `build_app` はテストで認証なしの名刺を組み立てられる余地を残さず、仕事 API を持つアプリには
  必ず空でないトークンを要求する。
- 導入手順に、安全なトークンの生成方法と、本体・各 A2A エージェントへ同じ値を渡す設定を記載する。

## Slack 外からの依頼キュー

依頼ファイルは次の状態遷移で処理する。

1. pending ファイルを同じファイルシステム内の processing 名へ atomic rename し、処理権を取る。
2. 入力を検証する。テーマ不明や空の本文など、再試行しても直らない入力は問題を通知して削除する。
3. Slack へ投稿し、通常の依頼として `submit` する。
4. 投稿と投入が成功したら processing ファイルを削除する。
5. Slack 障害などの一時的な例外では processing ファイルを pending に戻し、次の巡回で再試行する。

同じプロセス内での二重処理と、処理途中の例外による依頼消失を防ぐ。プロセスが強制終了して
processing ファイルが残った場合は、次回起動または巡回時に回収して pending と同様に扱う。

## 音声設定の復元

- 「聞く」の正は本体と voice プロセスが共有する SQLite の設定値とする。
- voice プロセス起動時に `voice.listening` を読み、`VoiceSession.run(listening=...)` の初期値に使う。
- 起動後の変更は従来どおり App Home から A2A の `listen` イベントで即時反映する。
- これにより、voice プロセスだけが再起動しても App Home の表示と実状態を一致させる。

## 「知らせる」単独での読み上げ

- 会話用 Realtime セッションが動作中なら、既存接続へ通知を投入する。
- 「聞く」が無効で会話用セッションがない場合は、通知専用の短命 Realtime セッションを開く。
- 通知専用セッションはマイクを開かない。通知テキストを1件送り、音声応答の完了を待って切断する。
- A2A の通知応答は読み上げ完了を待たない。`VoiceSession` がバックグラウンドタスクとして管理する。
- 複数通知は同時再生させず、受信順に処理する。
- 接続不能や API エラーはログへ残すが、本体の完了済み作業には影響させない。
- voice プロセス終了時は、通知タスクをキャンセルし、WebSocket とスピーカーを確実に閉じる。
- 読み上げた通知は、会話中の通知と同様に音声ジャーナルへ残す。

## 大学エージェントの Notion 権限

現実装を正式仕様とする。

- 大学エージェントの Claude は、授業・課題の読み取りに加え、課題の状態更新と課題ページの作成ができる。
- 削除、移動、複製、データベース作成などは許可しない。
- Claude の Notion コネクタは技術上、道具単位で授業ホームだけに限定できない。
- 専用の Claude プロファイル、共有する Notion ページ、`prompts/course.md` の指示で操作範囲を制約する。
- この制約と残るリスクを `docs/agents.md` と `deploy/README.md` に明記する。

## 自己改善の説明

`README.md` の説明を実装済みの承認フローに合わせる。要望の記録後、案、実装、取り込みの各段階で
依頼者の承認を得てから push・入れ替えを行うことを明記し、無承認で自動 push するような表現をなくす。

## テスト

各挙動はテストを先に追加し、期待した理由で失敗することを確認してから実装する。

- トークン未設定では A2A アプリ構築またはサーバー起動が失敗する。
- 公開 endpoint はトークンなしで読め、仕事 API は正しい Bearer トークンだけを受け付ける。
- 外部依頼は成功時だけ削除され、一時失敗時には再試行可能な状態へ戻る。
- 不正な外部依頼は通知後に破棄される。
- 残存した processing ファイルは再起動後に回収される。
- 保存済みの「聞く」設定が voice 起動時に復元される。
- 会話中の通知は既存接続を使い、非会話中の通知はマイクなしの短命接続を使う。
- 複数通知は順番に読み上げられ、失敗時と終了時にもリソースが残らない。
- 最後に全テストと `ruff check .` を実行する。

## 対象外

- A2A executor の共通基底・共通リクエスト型へのリファクタリング
- `Assistant` の Slack gateway、dispatcher、run coordinator 等への分割
- Notion 書き込みを Python API へ移すこと
- 音声モデル、声、会話人格の変更
