# Research Support Assistant 実装プラン

`doctor-ai-concept.pdf` の構想を、自分ひとり用の研究支援アシスタント「Ezra」として作るためのプラン。
2026-09-17 の設計の確認（grilling）で決めた内容をまとめる。まだ実装はしていない。

## 1. 目標と進め方

- 最終目標は、PDFの全機能を作り、音声で議論しながら研究を進められるようにすること
- まず「Slackで依頼 → Botが実行 → 同じスレッドに経過と結果が返る」という中心の流れ（フェーズ1）を作る。そのあと、使いながら機能を広げる
- 当面GPUやHPCは使わない。ただし構成はPDFと同じにし、あとで計算先を足せるようにしておく
- 研究分野はBotの設定では決めず、テーマごとの `CLAUDE.md` に書く

## 2. 全体の構成

| 役割 | 場所 | フェーズ1での中身 |
|---|---|---|
| 考える・調べる | Codex App | `~/research/` をプロジェクトとして開き、結果のファイルを読む。スレッドの経緯は Ezra が `.ezra/threads/` に書き出したものを読む（Slack MCP は Codex での対応が確認できたら足す）。音声での議論はCodexのChatGPT Voiceを使う |
| 作業を依頼する | 個人Slack | 新しく作ったワークスペース。チャンネルは4種類 |
| 実行する | Slack Bot（このリポジトリ） | 自分のMacで動かす。中で `claude -p` を呼び、ジョブは `pueue` で走らせる |
| ファイルを置く | `~/research/` | PDFの「Share」の代わり |
| 知見を残す | Notion | フェーズ1〜2では手で使ってみるだけ。Botとはフェーズ3でつなぐ |

Codex側は読むだけにし、実行はBotだけが行う。

## 3. 決めたことと理由

### Slack

| 項目 | 決めたこと | 理由 |
|---|---|---|
| ワークスペース | 個人用を新しく作る | Botを自由に入れられ、権限の申請が要らない |
| チャンネル | PDFどおり4種類（研究全体 / 中長期の方針 / 研究テーマごと / Assistantの改善） | PDFの構成に合わせる |
| 受け取り方 | Socket Mode | 反応が早く、公開URLが要らないのでMacの中でも動く |
| 反応する条件 | スレッドの外ではメンションが必要。Botが動いているスレッド内では、メンションなしで続けられる | メモを書いても反応しない。スレッド内の議論は自然に続けられる |
| 経過の返し方 | 1つのメッセージを `chat.update` で書き換えて、いまの作業を伝える。終わったら、結果と図を新しい返信で送る | スレッドが散らからない |
| 同時に来た依頼 | 違うスレッドの依頼は最大2件まで並行して処理する。同じスレッドの中は順番に処理する | 文献調査と分析を同時に頼んでも待たされない |
| 指示できる人 | 自分のSlackユーザーIDだけ | 安全のため |
| 依頼の送り方 | 最初は、Codexが作った依頼文とCSVを自分で貼る。慣れたら、CodexがSlack MCPで投稿する（投稿前に自分で確認する） | 最初は、どんな依頼文ならうまく動くかを目で確かめて、テンプレートを固める |

### Bot

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 言語 | Python（uv）+ Slack Bolt for Python | 研究のスクリプトと同じ言語でそろう |
| 実行エンジン | Claude Code CLI（`claude -p`）。サブスクリプションで動かす | PDFの「Claude Code + skill」そのまま。今の skill や設定を使える |
| スレッドと会話 | 1スレッド = 1セッション（`--resume`）。セッションが失われたら、スレッドの履歴をプロンプトに入れて新しいセッションで復元する | ふだんは文脈がそのまま残り、サーバーを移したときも止まらない |
| 許す操作 | 作業用ディレクトリの中の読み書き、Bash、Web検索、Webページの取得。Claude Code の sandbox を有効にする | 自分のMacで確認なしに動かすので、影響をテーマのディレクトリの中に閉じ込める |
| 動かす場所 | 自分のMac。`launchd` に登録し、ログイン時に起動して、落ちたら再起動する | 開発中は手元の方が直しやすい。Mac miniに移すときも同じ設定を使える |
| 秘密情報 | `~/.config/zsh/local/research-assistant.zsh` に置く。起動用のシェルスクリプトでこれを読み込んでからBotを起動する | `launchd` からは `~/.zshrc` が読まれないため。置き場所は今の決まりのまま |
| Botの名前 | Ezra（エズラ）。メンションは `@Ezra` | ヘブライ語で「助ける者」。落ち着いた響きで、音声でも呼びやすく、カタカナの表記がぶれにくい |

### テーマと作業用ディレクトリ

- 1チャンネル = 1テーマ = `~/research/<チャンネル名>/`
- Botを新しいチャンネルに招待すると、ディレクトリと `CLAUDE.md` のひな形を自動で作る
- どのチャンネルが研究全体・中長期の方針・Assistantの改善用かは、設定ファイルで決める
- 研究全体と中長期の方針のチャンネルでは、すべてのテーマを読むだけにし、書き込みは `~/research/_overview/` だけにする
- Assistantの改善のチャンネルでは、要望をこのリポジトリの `docs/backlog.md` に記録するだけにする。Botが自分のコードを直すのは、フェーズ6で承認ボタンを作ってから

```
~/research/
├── _overview/            # 研究全体・中長期の方針のチャンネルが書く場所
└── <theme>/
    ├── CLAUDE.md         # テーマの前提、研究分野、ジョブにする基準など
    ├── inputs/           # 依頼に添付されたCSVなど
    ├── outputs/          # 図や集計結果。新しくできたファイルをスレッドに添付する
    ├── logs/             # ジョブのログ
    └── papers/           # 文献調査で見つけた論文のメタデータと要約
```

### 作業

| 項目 | 決めたこと | 理由 |
|---|---|---|
| フェーズ1で任せる作業 | 文献調査と、データ分析・CPUでの実験 | GPUなしでPDFの流れを再現しやすい。コードの修正は安全対策が要るので、フェーズ6に回す |
| 文献調査 | Web検索に加え、arXiv と Semantic Scholar のAPIを使うskillを作る。結果は `papers/` に保存する | 絞り込みができ、同じ論文を二度調べずに済む |
| 時間のかかる作業 | 数分以上かかりそうな作業は `pueue` のジョブにする（Claudeが判断する。基準は `CLAUDE.md` に書く） | 自作するとBotの再起動や同時実行の制御でつまずく |
| ジョブの操作 | Claudeには `submit / status / cancel` の3つだけを見せる。中身は `pueue` | HPCをつなぐときは中身をSLURMなどに差し替える |
| ジョブの制限 | `submit` は、テーマのディレクトリの中にあるスクリプトだけを受け付ける。作業ディレクトリもテーマに固定する | `pueue` のジョブは sandbox の外で自分の権限のまま動くため。スクリプトの中身までは縛れないので完全には防げないと理解したうえで使い、フェーズ6で承認の仕組みとあわせて見直す |
| ジョブが終わったら | Botが毎分 `pueue status --json` を確認する。終わったジョブがあれば、スレッドのセッションを `--resume` で再開し、「ジョブXが終わった、出力はここ」と伝える。Claudeが集計して図を作り、スレッドに報告する | PDFの「実験が終わると図が返ってくる」体験の中心 |

## 4. 処理の流れ

### 新しい依頼

1. スレッドの外でメンションされたメッセージを受け取る。自分のユーザーIDかを確認する
2. チャンネルからテーマと作業用ディレクトリを決める。添付ファイルは `inputs/` に保存する
3. 👀 のリアクションをつけ、経過用のメッセージをスレッドに送る
4. テーマのディレクトリで `claude -p --output-format stream-json` を起動し、セッションIDをSQLiteに保存する
5. 流れてくるイベント（ツールの呼び出しなど）から、経過用のメッセージを書き換える
6. 終わったら、結果の文章を返信する。`outputs/` に新しくできたファイルを添付する

### スレッド内の返信

- 保存したセッションIDで `claude -p --resume` を実行する。セッションが見つからなければ、スレッドの履歴から復元する
- そのスレッドで処理中なら、終わってから順番に処理する

### ジョブ

- Claudeが skill から `submit` を呼ぶ。Bot側はジョブIDとスレッドの対応をSQLiteに保存し、スレッドに「ジョブを投入した」と書く
- 終わったら、上の「ジョブが終わったら」の流れで報告する

## 5. 主な部品

| 部品 | 役割 |
|---|---|
| `app` | Slack Bolt（Socket Mode）の受け口。反応する条件の判定と、ユーザーの確認 |
| `themes` | チャンネル、テーマ、ディレクトリの対応。ひな形を作る |
| `runner` | `claude -p` の起動、stream-json の読み取り、並行数の制御 |
| `sessions` | SQLite。スレッド ↔ セッション、ジョブ ↔ スレッド、実行時間の記録 |
| `reporter` | 経過用メッセージの書き換え、結果の返信、ファイルの添付 |
| `jobs` | `pueue` を包んだ `submit / status / cancel` と、毎分の状態確認 |
| `skills/` | 文献調査（arXiv / Semantic Scholar）、ジョブの投入、結果の報告の約束事 |
| `deploy/` | `launchd` の plist と、起動用のシェルスクリプト |

Botが1回動いた時間は、フェーズ1のうちから `sessions` に記録しておく。フェーズ5の「Assistantの稼働時間」にそのまま使える。

## 6. フェーズ1の実装ステップ

各ステップの終わりに、書いてある確認を実際に行う。

1. **準備**: このフォルダで `git init`。uvのプロジェクトを作る。Slackのワークスペース、4種類のチャンネル、Slack App（Socket Mode、必要なscope）を作る。`pueue` を Homebrew で入れる
   - 確認: トークンを読み込み、Botがオンラインになる
2. **受け取りと返信**: メンションに反応し、自分以外を無視し、固定の文をスレッドに返す
   - 確認: 自分のメンションに返信し、スレッド外のメンションなしのメッセージには反応しない
3. **テーマ**: チャンネルに招待したら、ディレクトリと `CLAUDE.md` を作る。設定ファイルで、研究全体・中長期の方針・Assistantの改善のチャンネルを決める
   - 確認: 新しいチャンネルに招待すると `~/research/<name>/` ができる
4. **Claudeの実行**: `claude -p` を起動し、経過用メッセージを書き換え、結果を返す。sandboxと許す操作を設定する
   - 確認: 「このディレクトリの中身を教えて」に答える。テーマの外に書き込もうとすると止まる
5. **スレッドとセッション**: `--resume` での続き、履歴からの復元、並行数の上限（2）、同じスレッド内は順番に処理
   - 確認: 返信で前の内容を覚えている。SQLiteを消しても、スレッドの履歴から続けられる
6. **ファイル**: 添付されたCSVを `inputs/` に保存する。`outputs/` の新しいファイルをスレッドに添付する
   - 確認: CSVを渡して図を作らせると、図がスレッドに返る
7. **ジョブ**: `pueue` を包み、ジョブ投入のskillを作る。終わったら状態を検知し、セッションを再開して報告する
   - 確認: 数分かかるスクリプトをジョブにし、終わったら図つきで同じスレッドに報告が返る
8. **文献調査**: arXiv と Semantic Scholar のskillを作り、`papers/` に保存する
   - 確認: 「◯◯の先行研究を調べて」で、要約と `papers/` のファイルができる
9. **特別なチャンネル**: 研究全体と中長期の方針のチャンネルは、読むだけと `_overview/` への書き込み。Assistantの改善のチャンネルは `docs/backlog.md` への追記
   - 確認: 研究全体のチャンネルからテーマのファイルを書き換えようとしても、止まる
10. **常時起動**: `launchd` の plist と起動用のスクリプト。launchd からは `~/Documents` を読めないので、リポジトリはその外に置く
    - 確認: Macを再起動したあとも動く。プロセスを止めても立ち上がる
11. **Codex側の設定**: Codex App で `~/research/` を開く。依頼文のテンプレートを作る（`docs/codex.md`）
    - 確認: Codexで結果のCSVとスレッドを読んで議論し、依頼文を作れる

## 7. 完成基準とその後のフェーズ

### フェーズ1の完成基準

1. PDFの03ページの流れを、GPUなしで最後まで一度通す。Codexで議論する → Slackに依頼とCSVを送る → ジョブが走る → 図つきで同じスレッドに返る → そのスレッドの続きで追加の依頼ができる
2. 文献調査の依頼で、要約と `papers/` への保存までできる
3. 実際の研究で1週間使い、`#assistant-improve` にたまった要望の中で、深刻なものを直す
