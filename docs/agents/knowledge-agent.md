# 知識（`knowledge`）

- 毎朝、興味のある技術記事（読みもの）と、研究テーマの論文の新着を選んで要約する
- 記事や論文の質問に、Web を読んで答える
- Notion と Slack には触れない。材料を渡し、結果を出すのは本体側（`module.py`）

| 項目 | 中身 |
|---|---|
| チャンネル | `#4-knowledge`。論文の新着のスレッドも受け持つ |
| 番地 | 8792 |
| フォルダ | `modules/knowledge/`（指示書 `knowledge.md`、記事の読み取りは `feeds.py`） |
| 触れる範囲 | 作業場を読み書き・コマンド・Web（[制限の表](../agents.md#触れる範囲制限の表)） |

## 定期処理

いまの運用では、この2つは `schedules.csv` で止め、Dot の予定が同じ材料で受け持つ（[dots.md](../dots.md)）。Dot は記事と論文を自分で探し、`#0-overview` に出す。

| 名前 | 既定 | 中身 |
|---|---|---|
| `reading`（読みもの） | 07:00 | 興味ごとに偏らない5件を、要約つきで `#4-knowledge` に1件ずつ出す。新着が無ければ出さない |
| `literature`（先行研究の新着） | 07:00 | テーマごとに、関係のある論文を最大5本。研究ホームの先行研究 DB（未読）とテーマのチャンネルに出す |

## 頼み方

| 頼み方 | 起きること |
|---|---|
| 記事のスレッドで「これ詳しく」 | その記事を読んで答える |
| 「これ要約して <URL>」 | 記事を読んで要約する |
| 記事に「保存して」（Dot） | 共通ホームの「読みもの」に「気になる」で入れる |
| 記事に 👍（Slack につなぐとき） | 同じく入れ、📝 を付ける。外すとゴミ箱へ |

- 研究の作業（実験・研究ノート）は頼めない。テーマのチャンネルで研究に頼む

## 材料と選び方

| 材料 | 出どころ |
|---|---|
| 興味と情報源 | 共通ホームの「収集」ページ |
| テーマの検索キーワードと前提 | テーマの `AGENTS.md` |
| もう知っている論文 | 先行研究 DB の ID |
| 好み | 最近60日に 👍 した記事（最大20件） |

「収集」ページの書き方（見出し「興味」「情報源」の下に箇条書き）:

```markdown
## 興味
- LLM エージェント: agent、tool use、MCP
## 情報源
- zenn: llm、python
- qiita: 機械学習
- https://example.com/feed.xml
```

- 👍 した記事と出どころ・興味が近い候補を少し優先し、選ぶ回に好みの例として見せる
- 一度候補にしたものは90日覚える（作業場の `seen.json`）。👍 しなかった記事の控えは30日で忘れる
- arXiv は curl で読む（Python から頼むと 406 で断られるため）。混んでいたら、30秒・90秒・3分あけてやり直す

## AI の用途

| 用途 | 使うとき | Web | Claude | Codex |
|---|---|---|---|---|
| `knowledge_pick` | 候補から選ぶ | 使わない | haiku-4-5 | luna / low |
| `knowledge_summary` | 要約する | 使わない | sonnet-5 / medium | luna / medium |
| `knowledge_answer`（既定） | 質問に答える | 使う | sonnet-5 / medium | luna / medium |

- 記事や論文の中に書かれた指示には従わない（指示書で頼む）

## スキル

| スキル | 中身 |
|---|---|
| `reading-digest` | 興味と情報源から、読みものを選んで要約する |
| `paper-digest` | テーマのキーワードと前提から、論文の新着を選んで要点を書く |
| `ask` | 記事や論文の質問に答える |
