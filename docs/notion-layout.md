# Notion のレイアウト方針

フェーズ3（Notion をつなぐ）の前に、Notion を手で使い始めるための方針。
構想資料で Notion は「計画・考察・Task を記録し、次の議論と定期実行に使う」場所。この役割に絞って形を決める。

## 1. 原則

### 置き場所を分ける

| 場所 | 置くもの | 置かないもの |
|---|---|---|
| Slack | 依頼、経過、結果のやり取り | 読み返したい結論（流れて見つからなくなる） |
| `~/research/`（ファイル） | データ、スクリプト、図、ログ、論文のメモ | 状態の管理（進捗、期日） |
| Notion | 計画、考察、Task とその状態、中長期の方針 | データや図の実物（リンクか要約だけにする） |

同じ内容を2か所に書かない。Notion にはファイルのパスや Slack のスレッドへのリンクを置き、実物はそれぞれの場所に残す。

### テーマで全部をつなぐ

1テーマ = 1 Slack チャンネル = 1 ディレクトリ = Notion の「テーマ」データベースの1行。
テーマの名前は、Slack のチャンネル名と同じにする（例: `ezra-trial`）。

### 書く人を分ける

| 書く人 | 書くもの |
|---|---|
| 自分 | テーマの目的、計画、考察、Task を作る、マイルストーン |
| Ezra（フェーズ3以降） | Task の状態と結果、Daily と振り返りのページ |
| Codex | 振り返りの結論（自分が貼るか、Codex が書く） |

Ezra は、自分が書いたページの本文を書き換えない。Ezra が触るのは、決めたプロパティと、Ezra が作ったページだけにする。

## 2. 全体の構成

```
🔬 研究ホーム（ページ）
├── ホームに置くビュー: 自分の Task、最近の Daily と振り返り、進行中のテーマ、近いマイルストーン
├── 🗂 テーマ（データベース）
├── ✅ Task（データベース）
├── 📝 ノート（データベース）: 計画 / 考察 / Daily / 振り返り / 議論メモ
├── 🧭 中長期の方針（ページ）
│   └── 🏁 マイルストーン（データベース）
└── ⏱ 研究時間（データベース。フェーズ5で作る）
```

データベースは4つだけにする。「計画」「考察」「Daily」などを別々のデータベースにすると、テーマごとにまとめて見るのが難しくなるので、「ノート」の「種類」で分ける。

## 3. データベース

### 🗂 テーマ

| プロパティ | 種類 | 値・使い方 |
|---|---|---|
| 名前 | タイトル | Slack のチャンネル名と同じ |
| 状態 | セレクト | 進行中 / 保留 / 完了 |
| 目的 | テキスト | 1〜2文。何を明らかにしたいか |
| Slack | URL | チャンネルへのリンク |
| ディレクトリ | テキスト | `~/research/<名前>/` |
| Task | リレーション | ✅ Task |
| ノート | リレーション | 📝 ノート |
| マイルストーン | リレーション | 🏁 マイルストーン |
| 最終更新 | 最終更新日時 | 自動 |

ビュー: 「進行中」（状態 = 進行中、リスト）と、最初からある表。

テーマの前提や検索キーワードは、Ezra が読む `CLAUDE.md` を正とする。Notion には目的だけを書き、詳しくは `CLAUDE.md` を見る。

### ✅ Task

| プロパティ | 種類 | 値・使い方 |
|---|---|---|
| タイトル | タイトル | 動詞で終える（例: 条件Cで精度を測る） |
| テーマ | リレーション | 🗂 テーマ（1つ） |
| 状態 | ステータス | 未着手 / 今夜やる / 実行中 / 確認待ち / 完了 |
| 担当 | セレクト | 自分 / Ezra |
| 優先度 | セレクト | P0 / P1 / P2（構想資料の実験計画 CSV と同じ） |
| 期日 | 日付 | 任意 |
| Slack | URL | 依頼や結果のスレッド |
| 結果 | テキスト | 1〜3行。Ezra が書く |
| 作成日 | 作成日時 | 自動 |

ビュー:

- 「ボード」: 状態ごとの列
- 「今夜」: 担当 = Ezra かつ 状態 = 今夜やる（フェーズ3で Ezra が 01:30 に読む）
- 「確認待ち」: 状態 = 確認待ち（自分が返事をするもの）
- 「今週の自分」: 担当 = 自分、期日が今週

### 📝 ノート

| プロパティ | 種類 | 値・使い方 |
|---|---|---|
| タイトル | タイトル | 例: 条件Bで精度が上がった理由の考察 |
| 種類 | セレクト | 計画 / 考察 / Daily / 振り返り / 議論メモ |
| テーマ | リレーション | 🗂 テーマ（複数可。Daily などは空でよい） |
| 日付 | 日付 | 書いた日、または対象の日 |
| 書いた人 | セレクト | 自分 / Ezra / Codex |
| Slack | URL | 元になったスレッド |
| ファイル | テキスト | 関係するファイルのパス（`outputs/…`、`daily/…`） |

ビュー: 「最近」（日付の新しい順）、「種類ごと」（ボード）、「Daily と振り返り」（カレンダー）。

ページのテンプレート:

- **計画**: 目的 / 仮説 / 条件（何を変えて何を測るか） / 判断の基準（どうなったら仮説を支持するか） / Ezra への依頼
- **考察**: 問い / 結果（図やスレッドへのリンク） / 解釈 / 次の一手
- **議論メモ**: 話した相手（Codex、指導教員など） / 論点 / 決めたこと / 宿題

### 🏁 マイルストーン

| プロパティ | 種類 | 値・使い方 |
|---|---|---|
| 名前 | タイトル | 例: 学会の締切、中間発表 |
| 期日 | 日付 | |
| テーマ | リレーション | 🗂 テーマ |
| 状態 | セレクト | 予定 / 準備中 / 済み |
| メモ | テキスト | 何が必要か |

ビュー: 「タイムライン」（期日順）。

## 4. 研究ホーム

ホームのページには、データベースの「リンクドビュー」を上から次の順に並べる。

1. **自分の Task**: ✅ Task から、担当 = 自分 かつ 状態 ≠ 完了。期日の近い順
2. **最近の Daily と振り返り**: 📝 ノートから、種類 = Daily または 振り返り。新しい順
3. **進行中のテーマ**: 🗂 テーマから、状態 = 進行中
4. **近いマイルストーン**: 🏁 マイルストーンから、期日が今日以降。近い順

朝はこのページを開けば、その日にやることと、議論の起点がそろう。

## 5. Ezra とのつながり（フェーズ3）

決めた内容と理由は `docs/plan.md` の9章。

| 流れ | フェーズ2まで | フェーズ3から |
|---|---|---|
| 夜間の Task | Slack の 🌙 | ✅ Task の「今夜」ビューを Ezra が読む。🌙 は、Notion に Task を作る入口として残す |
| Task の結果 | スレッドと ✅ | 加えて、Task の「状態」と「結果」を Ezra が書く |
| Daily と振り返り | `_overview/daily/`、`reviews/` と Slack | 加えて、📝 ノートにページを作る。ファイルは Codex が読むために残す |
| 計画と考察 | なし | 📝 ノートの計画と考察を、Daily の材料として Ezra が読む |

Ezra 本体が Notion の API（コネクト「Ezra」のトークン）で読み書きする（`src/ezra/notion_store.py`）。Claude には Notion を触らせない。コネクトに許可するのは「研究ホーム」の中だけ。

## 6. 手で使い始める手順（数日）

2026-09-17 に、`uv run ezra-notion-setup <研究ホームのページID>` で、2〜4 章の構成（データベース、リレーション、ビュー、ホームの4つの欄）と、テーマ `ezra-trial` を作成済み。作ったものの ID は `~/.local/state/ezra/notion.json` にある。

API ではページのテンプレートを作れないため、計画・考察・議論メモの書き方は「ノート」データベースの説明文に書いてある。テンプレートにしたいときは、Notion の画面で作る。

毎日やること:

- 朝: Slack の Daily を読み、今日の Task を2〜3件作る
- 日中: Ezra の結果を見て、気づいたことを「考察」ノートに1つ書く
- 夜: Codex で振り返り、結論を「振り返り」ノートに貼る

数日たったら、使わなかったプロパティ、足りなかった欄、ビューの使い勝手を `#assistant-improve` に書く。これをもとにフェーズ3を設計する

## 7. 決めること

| 項目 | 推奨 | 理由 |
|---|---|---|
| 論文を Notion に置くか | 置かない。`papers/` のまま、考察ノートからリンクする | 文献調査は Ezra がファイルで管理しており、二重管理になる |
| Daily と振り返りを Notion にも置くか | フェーズ3で置く（ファイルも残す） | 朝に Notion のホームで読めるようにする。Codex はファイルを読む |
| Task の正をどこにするか | フェーズ3からは Notion。🌙 は Task を作る入口にする | 状態や期日を見渡せるのは Notion |
| テーマの前提と検索キーワードの正 | `CLAUDE.md` | Ezra が毎回読むもの。Notion には目的だけ |
| ワークスペース | 個人ワークスペースの中に「研究ホーム」を1つ | 研究以外のページと混ざらず、Ezra に読ませる範囲も絞れる |
