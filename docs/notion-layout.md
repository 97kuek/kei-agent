# Notion のレイアウト方針

Notion に何をどう置くか。Notion は「計画・考察・Task を記録し、次の議論と定期実行に使う」場所で、
この役割に絞って形を決めている。つなぎ方の理由は [`design.md`](design.md#8-notion)。

## 1. 原則

### 置き場所を分ける

| 場所 | 置くもの | 置かないもの |
|---|---|---|
| Slack | 依頼、経過、結果のやり取り | 読み返したい結論（流れて見つからなくなる） |
| `~/research/`（ファイル） | データ、スクリプト、図、ログ、論文のメモ | 状態の管理（進捗、期日） |
| Notion | 計画、考察、Task とその状態、中長期の方針 | データや図の実物（リンクか要約だけにする） |

同じ内容を2か所に書かない。Notion にはファイルのパスや Slack のスレッドへのリンクを置き、実物はそれぞれの場所に残す。

### テーマで全部をつなぐ

1テーマ = 1 Slack チャンネル = 1 ディレクトリ = Notion の「テーマ」データベースの1行。
テーマの名前は、Slack のチャンネル名と同じにする（例: `#vlm-counting` → `vlm-counting`）。

### 書く人を分ける

| 書く人 | 書くもの |
|---|---|
| 自分 | テーマの目的、計画、考察、Task を作る、マイルストーン |
| Kei Agent | Task の状態と結果、共通ホームの日別記録 |
| Codex | 振り返りの結論（自分が貼るか、Codex が書く） |

Kei Agent は、自分が書いたページの本文を書き換えない。Kei Agent が触るのは、決めたプロパティと、Kei Agent が作ったページだけにする。

Kei Agent はデータベースとプロパティを名前で読むので、Notion の画面でデータベースやプロパティ、「状態」「種類」の選択肢の名前を変えない。変えるときは、このドキュメントと `src/kei_agent/notion.py`・`src/kei_agent/notion_store.py` も合わせて直す。

## 2. 全体の構成

```
Keitaro Ueki（共通ホーム、論理的な親）
├── 研究 Task／授業課題の今週のリンクドビュー
├── 予定カレンダー（既存の「今月の予定」を再利用）
├── 日別記録（Daily とレトプラを1日1行）
├── 研究ホームへのリンク
└── 授業ホームへのリンク

🔬 研究ホーム（既存の場所を維持）
├── ホームに置くビュー: 自分の Task、進行中のテーマ、近いマイルストーン
├── 🗂 テーマ（データベース）
├── ✅ Task（データベース）
├── 📝 ノート（データベース）: 計画 / 考察 / 議論メモ（移行前の記録は原本を保管）
├── 🧭 中長期の方針（ページ）
│   └── 🏁 マイルストーン（データベース）
└──（研究時間は Notion に置かない。人は Toggl、Kei Agent は `runs` テーブル）
```

研究ホームのデータベースは4つ。研究ノートの「計画」「考察」「議論メモ」はテーマごとにまとめる。大学・仕事を含む Daily とレトプラは共通ホームの `日別記録` を正本とし、研究ノートには新規作成しない。

## 3. データベース

### 🗂 テーマ

| プロパティ | 種類 | 値・使い方 |
|---|---|---|
| 名前 | タイトル | Slack のチャンネル名と同じ |
| 状態 | セレクト | 進行中 / 保留 / 完了 |
| 目的 | テキスト | 1〜2文。何を明らかにしたいか |
| Slack | URL | チャンネルへのリンク |
| ディレクトリ | テキスト | `~/research/<名前>/` |
| Task | リレーション | ✅ Task |
| ノート | リレーション | 📝 ノート |
| マイルストーン | リレーション | 🏁 マイルストーン |
| 最終更新 | 最終更新日時 | 自動 |

ビュー: 「進行中」（状態 = 進行中、リスト）と、最初からある表。

テーマの前提や検索キーワードは、Kei Agent が読む `CLAUDE.md` を正とする。Notion には目的だけを書き、詳しくは `CLAUDE.md` を見る。

### ✅ Task

| プロパティ | 種類 | 値・使い方 |
|---|---|---|
| タイトル | タイトル | 動詞で終える（例: 条件Cで精度を測る） |
| テーマ | リレーション | 🗂 テーマ（1つ） |
| 状態 | ステータス | 未着手 / 今夜やる / 実行中 / 確認待ち / 完了 |
| 担当 | セレクト | 自分 / Kei Agent |
| 優先度 | セレクト | P0 / P1 / P2（構想資料の実験計画 CSV と同じ） |
| 期日 | 日付 | 任意 |
| Slack | URL | 依頼や結果のスレッド |
| 結果 | テキスト | 1〜3行。Kei Agent が書く |
| 作成日 | 作成日時 | 自動 |

ビュー:

- 「ボード」: 状態ごとの列
- 「今夜」: 担当 = Kei Agent かつ 状態 = 今夜やる（Kei Agent が 00:00 に読む）
- 「確認待ち」: 状態 = 確認待ち（自分が返事をするもの）
- 「今週の自分」: 担当 = 自分、期日が今週

### 📝 ノート

| プロパティ | 種類 | 値・使い方 |
|---|---|---|
| タイトル | タイトル | 例: 条件Bで精度が上がった理由の考察 |
| 種類 | セレクト | 計画 / 考察 / Daily / 振り返り / 議論メモ |
| テーマ | リレーション | 🗂 テーマ（複数可。Daily などは空でよい） |
| 日付 | 日付 | 書いた日、または対象の日 |
| 書いた人 | セレクト | 自分 / Kei Agent / Codex |
| Slack | URL | 元になったスレッド |
| ファイル | テキスト | 関係するファイルのパス（`outputs/…`、`daily/…`） |

ビュー: 「最近」（日付の新しい順）、「種類ごと」（ボード）。旧 Daily・振り返りの原本は移行照合後も削除しない。

ページのテンプレート:

- **計画**: 目的 / 仮説 / 条件（何を変えて何を測るか） / 判断の基準（どうなったら仮説を支持するか） / Kei Agent への依頼
- **考察**: 問い / 結果（図やスレッドへのリンク） / 解釈 / 次の一手
- **議論メモ**: 話した相手（Codex、指導教員など） / 論点 / 決めたこと / 宿題

### 🏁 マイルストーン

| プロパティ | 種類 | 値・使い方 |
|---|---|---|
| 名前 | タイトル | 例: 学会の締切、中間発表 |
| 期日 | 日付 | |
| テーマ | リレーション | 🗂 テーマ |
| 状態 | セレクト | 予定 / 準備中 / 済み |
| メモ | テキスト | 何が必要か |

ビュー: 「タイムライン」（期日順）。

## 4. 研究ホーム

ホームのページには、データベースの「リンクドビュー」を上から次の順に並べる。

1. **自分の Task**: ✅ Task から、担当 = 自分 かつ 状態 ≠ 完了。期日の近い順
2. **進行中のテーマ**: 🗂 テーマから、状態 = 進行中
3. **近いマイルストーン**: 🏁 マイルストーンから、期日が今日以降。近い順

朝はこのページを開けば、その日にやることと、議論の起点がそろう。

## 5. Kei Agent とのつながり

| 流れ | いまの形 |
|---|---|
| 夜間の Task | ✅ Task の「今夜」ビューを Kei Agent が読む。Slack の 🌙 は、Notion に Task を作る入口 |
| Task の結果 | Task の「状態」と「結果」を Kei Agent が書き、Slack のスレッドにも返す |
| Daily とレトプラ | 共通ホームの `日別記録` に対象日ごと1行。ファイル（`~/kei-agent/overview/` の下）も残す。ページ本文を手で追記するときは「Kei Agent の本文ここまで」の下に置く（上は再生成の対象） |
| 計画と考察 | 📝 ノートの計画と考察を、Daily の材料として Kei Agent が読む |

Kei Agent 本体が Notion の API（コネクト「Kei Agent」のトークン）で読み書きする（`src/kei_agent/notion_store.py`）。
研究の Claude には Notion を触らせない。コネクトに許可するのは「研究ホーム」の中だけ。

授業用は別のコネクトと別のトークンで、`src/kei_agent_course/notion_sync.py` が書く。授業ホームの正本は「授業」「課題」「学習ログ」と、以下の学業記録3 DB の計6つである。
大学エージェントの claude が**読む**ぶんは、アカウントに付いている Notion 連携を使う。

### 授業ホームの学業記録

授業ホームには、成績HTMLをローカルで解析した派生データだけを置く。

| DB | 役割 |
|---|---|
| `📊 成績履歴` | 科目群、科目区分、授業名、成績、GP、単位、取得年度、取得済。識別子は非表示 |
| `🎓 単位要件` | 大区分、要件名、所定・既得・算入・残り単位、集計種別。`総合計` 行で卒業要件の全体を答える |
| `📈 GPA推移` | 春学期・秋学期・通算GPA。グラフは学期別だけを時系列順に表示し、`通算` 行は現在値として答える |

`授業` ← `課題`、`授業` ← `学習ログ`、`授業` ← `📊 成績履歴`、`📊 成績履歴` ← `🎓 単位要件` / `📈 GPA推移` の relation でつなぐ。過去の同名科目は年度・学期まで一致したときだけ成績と結び、複数候補なら結ばず確認対象として報告する。
成績と単位要件は科目群・科目区分が一意に一致する場合に結ぶ。英語・自然科学・専門選択必修は該当要件の区分と算入単位を照合し、必修または学系別専門の行に結ぶ。成績とGPAは年度・学期に加え、既存GPAの単位加重計算と一致する夏ク・秋ク・通年を結ぶ。2025年の「データ科学入門α」は春学期の公表値と照合済み。2025年冬クの「データ科学入門δ」は既存の秋学期・通算GPA値と整合せず、対象学期の根拠が得られるまでGPA relation を空欄に保つ。授業の `科目群`・`科目区分`・`必選区分`・`学期`・`曜日`・`状態` は各科目ページで選択する。

入力HTMLはNotionへ保存しない。`kei-agent-course-academic-import --dry-run <grades.html> <credits.html>` で予定を確認し、`--apply` で反映する。入力を消すのは反映件数の検証後、`--delete-inputs` を明示したときだけである。Notionに無い卒業要件を推測しない。

### 研究ログとW&B

研究のSQLiteはスレッド、ジョブ、再実行、ロックなどの運用状態の正であり、Notionへ置き換えない。研究ホームのNotionには、Daily・判断・実験の要約・W&B run URL・主要指標だけを非同期で投影する。完全なstdout、checkpoint、raw datasetはローカルに残す。W&B MCPは研究pluginにだけ追加し、既定は読み取りとする。

## 6. 作り方

`uv run kei-agent-notion-setup <研究ホームのページID>` で、2〜4 章の構成（データベース、リレーション、
ホームの4つの欄）を作る。作ったものの ID は `~/.local/state/kei-agent/notion.json` に残る。
授業用は `kei-agent-course-setup`（`~/.local/state/kei-agent/notion-course.json`）。

API で作れないものはノートのテンプレートだけなので、作り直したら手で空の枠を用意する。

- **テンプレート**（ノートの「計画」「考察」「議論メモ」）… Notion の画面で空のテンプレートを作れば、
  中身（名前、種類、書いた人、見出し）はセットアップのコマンドが書く
- **ビュー**（並び替え、絞り込み、列の順番）… Notion API `2026-03-11` で管理する。授業ホームは
  `kei-agent-course-layout` の dry-run を確認してから `--apply` し、`課題一覧`（科目・課題・締切・状態の順）と
  `GPA推移`（期間を横軸、GPAを縦軸にする折れ線）を統一する。既存の課題本文と `Untitled` DB はこの処理で変更しない

`kei-agent-course-setup <授業ホームID>` で学業記録の列を補った後、`python -m kei_agent_course.academic_layout` で変更件数を確認し、`--apply` で既存ページの識別子・成績分類・確実な relation と、`成績一覧`・`要件一覧`・`授業一覧`・`GPA推移` のビューを反映する。空欄のままの識別子があっても同じ行を再作成しないよう、移行は既存ページIDを保って行う。
`python -m kei_agent_course.academic_layout --history` で過去授業と未接続の relation を dry-run し、`--history --apply` で年度・学期・科目名が一意な過去授業を作って成績に結ぶ。終了済みの授業は Moodle の現行科目検索に含めない。以後の成績 HTML 取り込みでもこの連携処理を実行する。

使っていて足りない欄やビューに気づいたら、`#00_kei-agent` に書く。

## 7. 決めたこと

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 論文を Notion に置くか | 置かない。`papers/` のまま、考察ノートからリンクする | 文献調査は Kei Agent がファイルで管理しており、二重管理になる |
| Daily と振り返りを Notion にも置くか | 置く（ファイルも残す） | 朝に Notion のホームで読めるようにする。Codex はファイルを読む |
| Task の正をどこにするか | Notion。🌙 は Task を作る入口にする | 状態や期日を見渡せるのは Notion |
| テーマの前提と検索キーワードの正 | `CLAUDE.md` | Kei Agent が毎回読むもの。Notion には目的だけ |
| ワークスペース | 個人ワークスペースの中に「研究ホーム」を1つ | 研究以外のページと混ざらず、Kei Agent に読ませる範囲も絞れる |
