# 設計の決めごと

- Kei Agent を、コアに触らず、設定と自分のモジュールで作り替えられる形にしている
- ここには決めごとと理由だけを書く。動きは [`architecture.md`](architecture.md)、作り方は [`modules.md`](modules.md)

## 目標

- コアを触らず、設定と自分のモジュールだけで作り替えられる（fork で深く変えるのは止めない）
- 作り替えた人も、`git pull` でコアの更新をそのまま取り込める
- 担当や機能を足すのは「モジュールのフォルダを1つ足して、設定に1行書く」で済む

## 前提

- 言葉は日本語
- 動かすのは macOS（launchd）。常駐のさせ方は `deploy/` に閉じ込め、ほかの OS はあとで足せる形にする
- 名前は Kei Agent のまま。話し方と呼び方は `profile.md` で変える

## MCP クライアントと共通コード

- Dot は任意の MCP クライアント。依頼の実行・進捗・会話の継続・通知の保存は、クライアントの製品名によらず同じ MCP 契約で扱う
- クライアントは利用者との対話、依頼と `conversation` の対応、通知の配信を受け持つ。`accepted` の実行は `ticket` で `status` を確認し、通知は配信成功後だけ `notices(done=[...])` で確認済みにする
- Slack・通話・クラウド側の定期実行やプラグインはクライアント側の機能。別のクライアントをつないでも自動で備わるわけではない。共通コードはそれらの認証情報を引き継がない
- 機能の有無はモジュールの宣言で決める。旧設定の互換処理より、現在登録されている独自モジュールの宣言を優先する
- Daily・振り返りなどのローカル定期処理は任意で使える。クライアント側で同じ処理を動かす場合は `schedules.csv` で停止し、同じ目的の処理を二重に動かさない。停止・削除した処理は待機中の再実行も行わない
- Dot 用プロンプトと接続手順は構成例。個人の所属・対象リポジトリ・権限を共通の既定として扱わない

## Dot とローカル実行サービス

以下は同梱する Dot 構成の役割分担。共通コードの必須条件ではない。

- Kei Agent は Dot とローカル実行サービスを含むアシスタント全体。Slack の受け答えと決まった時刻の処理は Dot、作業場での AI 実行・秘密情報を使う取り込み・ジョブはローカル実行サービスが担当する。Mac を閉じていても Dot は答えられ、Mac を常に起こしておかなくてよいため
- ローカル実行サービスへの依頼は MCP サーバーを通す。Dot が選べるのは作業場・頼みごと・重さ・表で許した AI だけで、実行の制限は Mac 側が適用する
- 秘密情報（Moodle の書き出し URL・Toggl のキー）を使う取り込みは Mac に残す。Dot の予定には秘密情報を置く場所が無いため
- Outlook のメールと予定は Dot が直接読む。Teams・SharePoint は現在、会社の Claude を使う Mac の仕事担当が読む
- 大学の Notion・Box の質問と、知識の検索・要約・Notion 保存・定期処理は Dot が直接行う。大学の Mac プロセスは AI を持たず、Moodle の機械同期だけを受け持つ
- Moodle の ICS は起動・復帰時と30分ごと、API 設定時の提出・受験終了は10分ごとに同期する。朝だけの取り込みに依存しない
- 通話の Slack 記録は、投稿内容・目的・宛先について利用者の依頼と許可を確認して行う。個別投稿の許可を継続的な自動記録に広げない
- Slack の接続と通知の送信は Dot に一本化する。ローカル実行サービスは Outbox に通知を保存して MCP で渡す。Dot は配信できた ID だけを `notices(done=[...])` に返す。取得と配信済みの記録を分け、途中で処理が止まっても再取得できるため
- 取り込み結果の照合・通知の確認済み管理・実行状態の記録はコードで行い、Dot にはプラグインの選択と対話を任せる。締切の配信は Dot の予定だけが行う
- Dot のプラグインとローカルの connectors は別の設定。Notion・Box・Outlook・Google Calendar・Gmail・Google Drive・GitHub は Dot の接続を使う（[dots.md](dots.md#dot-側の設定)）

## コアとモジュール

| コア（枠だけ） | モジュール（機能） |
|---|---|
| MCP サーバーと通知の置き場、作業場からの担当の選択 | 研究・大学・仕事・知識・声・Notion |
| AI を動かす仕組み（provider・モデルの一覧・制限の表） | Daily・振り返り、時間記録、自己改善 |
| 保存（SQLite）、定期処理・実行状態の記録 | 自分で足したモジュール |
| セットアップ・点検・更新のコマンド、常駐 | |

- 要るのは Dot などの MCP クライアント・AI の provider 1つ・コアだけ。ほかはすべて任意
- 変わらない事実は `module.toml` に書き、動きは決まった差し込み口（`module.py`・`agent.py`）に書く
- コアとのやり取りは窓口（`kei_agent.api`・`kei_agent_a2a.api`）だけ。窓口の範囲が、枠の版で約束する中身
- モジュールの操作は `async head_action`、材料は `async head_materials` で MCP に渡す。Slack のボタン・入力画面・リアクションを処理する差し込み口は持たない（[modules.md](modules.md#modulepy)）
- 組み込みも自分のものも、同じ仕組みで読む。組み込みがそのまま作り方の見本になる
- 担当プロセスのコードもモジュールのフォルダに入れ、共通の1つのコマンドで起動する（`src/` や `pyproject.toml` を直さない）
- 朝の一覧や Daily の材料は、各モジュールが出す（大学なら締切、仕事なら会議）
- 会話の続きは provider のセッションと端末の記録で管理する。モジュールが履歴を読むときも端末の会話と通知を使い、Slack の履歴取得には頼らない

## 設定

- 構造（使うモジュール・チャンネル・時刻の既定）は設定ファイルが正本。日々の操作は MCP の道具で行う（時間記録の計測・メモ・Toggl の確認、投稿済みの読みものの保存・解除など。[architecture.md](architecture.md#mcp-サーバー)）
- モジュールのオンオフ・チャンネル・AI（engine・モデル）は、担当の表 `agents.csv` の1か所にまとめる。表計算ソフトで一覧して直せるため。同じものを `config.toml` にも書くと起動しない
- AI とアカウントを変えるのは `agents.csv` だけ
- 表で固定できるモデルも、コアの一覧の中だけ。明示したときだけの用途（`manual = true`）のモデルは固定できない
- 自分のものはリポジトリの外（`~/.config/kei-agent/`）。リポジトリには例だけを置く
- 秘密情報は、共通のものとモジュールごとのものに分ける。ほかのモジュールの鍵は、そのプロセスに載せない
- 秘密情報の場所は、いつも AI に読ませない場所に入る
- AI を持つ担当ごとに別のアカウントを使える（研究は個人、仕事は会社）。大学と知識にはローカル AI のアカウントを設定しない

## AI と安全

- 使ってよいモデルの一覧はコアに置き、モジュールはその中から用途ごとに選ぶ
- 別の provider や上のモデルへ、黙って切り替えない
- モジュールは、読むデータの区分・Notion・連携の道具を宣言する。超えることはコアが実行のときに止める
- 外の文・個人のデータ・外へ出す口の3つを、1回の実行に揃えない（外の文を材料にする用途は Web を外す）
- いちばん大事にするのは使いやすさ。縛るのは越えてはいけない線だけにして、迷ったら縛らない
- **越えてはいけない線**: 秘密情報・鍵とアカウントのフォルダを読まない、アカウントの違う担当の作業場を読まない（会社と個人を混ぜない）、作業場の外に書かない、会社のデータを読む実行は外へ出ない。Claude でも Codex でも同じ固さで守り、守れなければ始める前に止める（`tests/test_lines.py`）。plugin のフックは、明らかな違反を断る第二の防御
- **作法**（どの道具をどう使うか、手順、書き方）は指示書で頼むだけ。道具は線から決まる（モジュールは `[actor] data` に、会社のデータを読むかだけを書く）

## 担当ごとの決めごと

| 担当 | 決めごと |
|---|---|
| 研究 | 既存のフォルダやリポジトリには、なるべく触らない（[research-agent.md](agents/research-agent.md)）。保護フォルダは、はっきり許したときだけ |
| 大学 | モジュールは汎用にし、学校ごとの違いは学校の部品にする（早稲田はその1つ）。個人の履修科目はコードに持たない |
| 仕事 | Microsoft 365 は読むだけ。送信・予定の変更はしない。プロジェクトのコードは作業場の中だけに書き、push・デプロイはしない |
| 知識 | 検索・記事要約・Notion 保存・毎朝の選定は Dot が行う。Mac の `knowledge` は古い記事の `save_reading` 互換だけを持ち、actor・process・schedules は持たない |

## Notion

- ローカルからの読み書きは Notion ゲートウェイに一本化する。ローカルで API キーを持つのもゲートウェイだけ。Dot は別認証の Notion プラグインを使う
- ホームはモジュールごとに持てる。担当は、自分のホームの下だけに届く
- DB の名前と項目は「標準の形」として固定する。使うかどうかは任意

## 指示書

- コアの指示書は汎用に書き、個人の前提は `profile.md` から差し込む
- 細かく変えたい人は、同じ名前のファイルを `~/.config/kei-agent/prompts/` に置いて丸ごと差し替える

## 枠の版

- いまの版は `api = 2`。合わない版、使えない宣言や差し込み口は読み込まず、読み込み時に理由を知らせる。契約は [modules.md](modules.md#決まりごと)
- 枠（`module.toml` の形と窓口）を変えるときは版を上げ、変わった点と直し方を CHANGELOG に書く

## まだ作っていないこと

- `setup` で、外の文・個人のデータ・外へ出す口が揃ってしまうモジュールを断る
- `setup` の中で Notion の DB を作る（今は、ゲートウェイが動いてから `kei-agent-hub-setup` などで作る）
- macOS 以外での常駐
