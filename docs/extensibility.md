# 設計の決めごと

現在の実装を選んでいる理由。操作は [用途別ガイド](../README.md#したいことから読む)、実行契約は [実行基盤](architecture.md)、拡張契約は [モジュール](modules.md) を正本とする。

## MCP クライアントと共通コード

- Dot は任意の MCP クライアント。同梱の運用では、Slack・通話・クラウド連携・定期配信を受け持つ。共通コードは製品名に依存せず、依頼・会話番号・受付番号・結果・通知を MCP で扱う
- クライアントは対話と配信、Mac は実行と記録を担当する。通知の取得と確認応答を分け、途中で止まっても未配信を再取得できるようにする
- 大学・知識は Dot の論理的な担当で、別の Mac AI を必要としない。クラウドで読める Notion・Box・Web は Dot が扱い、Mac を閉じていても答えられる
- Moodle・Toggl の秘密情報を使う機械処理と、作業場・ローカルジョブは Mac に置く。Dot の接続と Mac の認証情報は独立させる
- 通話の Slack 記録は利用者の依頼と投稿権限に従う。個別投稿の許可を継続記録へ広げない
- 同じ目的の定期処理を Dot と Mac で二重に動かさない。Dot の予定を使う構成では Mac の `daily`・`review`・`night` を停止する

## コアとモジュール

| コアが持つもの | モジュールが持つもの |
|---|---|
| MCP・通知・作業場の選択・実行状態 | 研究・大学・仕事などの用途の処理 |
| AI の起動・モデルの一覧・権限制御 | 用途ごとのモデル選択と指示書 |
| 設定・SQLite・定期処理の呼び出し | Daily・時間記録・夜間 Task・取り込み |
| 導入・点検・常駐の枠 | 独自のコマンドと担当プロセス |

- 固定の宣言は `module.toml`、動作は `module.py`・`agent.py` などの差し込み口に置く。組み込みも追加モジュールも同じ窓口で読み込み、枠内の拡張に `src/` や `pyproject.toml` の変更を求めない
- モジュールは `kei_agent.api` / `kei_agent_a2a.api` だけを読み込む。依存方向を固定して、機能の追加がコアの内部構造へ波及しないようにする
- `head_action` と `head_materials` は既存の操作・材料を渡す窓口。公開 MCP ツール名は `operations/hands_server.py` に固定されており、新しい `head_action` だけでは増えない。新しい MCP ツールの公開にはコアの契約変更が要る
- 枠は `api = 3`。版2も読み込めるが、未対応の版・宣言・差し込み口は理由を示して拒否する。契約を変更するときは版と変更手順を更新する

## 設定と指示書

- モジュールのオンオフ・チャンネル・AI・アカウントは `agents.csv`、時刻は `schedules.csv` にまとめる。同じ設定を `config.toml` に重ねて持たない
- 個人のプロフィール・接続情報・設定はリポジトリの外に置く。汎用の指示書に `profile.md` を足し、必要なら同名の指示書を `~/.config/kei-agent/prompts/` で差し替える
- 学校ごとの差は大学モジュールの学校別部品に置く。個人の履修科目やプロフィールを共通コードに埋め込まない
- 既存の研究・仕事のフォルダと前提ファイルを尊重し、会話とジョブの状態は SQLite、知見とタスクは Notion に分ける

## AI と安全

- モデルの許可一覧はコア、用途ごとの選択はモジュールに置く。provider・上位モデルへ自動で切り替えず、使えなければ理由を返す
- 権限は宣言と作業場から決め、実行時に強制する。秘密情報・他アカウント・作業場外の書き込みを遮断し、会社のデータを読む実行は Web・コマンドの通信を許さない。Claude と Codex の両方でこの境界を守る
- 道具の使い方・提出しないなどの作法は指示書に置く。plugin のフックは明らかな違反を断る追加の防御で、実行時の境界の代わりにはしない
- ローカルの Notion キーはゲートウェイだけが持ち、利用者ごとのトークンとホームの子孫チェックで範囲を絞る。Dot の Notion プラグインは別認証とする
- 共通の DB・項目名を固定し、処理間で同じ意味として扱う。各ホームやモジュールの利用は任意
