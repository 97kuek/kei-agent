# 使い方

- Slack で Kei Agent に頼むときの案内
- デプロイ方法は [`deploy/README.md`](../deploy/README.md)、詳細な設計は [`design.md`](design.md)を参照

![Kei Agent の1日](schedule.png)

## チャンネルの分け方

- 先頭の番号はサイドバーの並び順のためのもので、番号を変えても同じテーマを指し続ける
- フォルダ名と Notion のテーマ名は、番号を外したもの

| チャンネル | 何を頼むか | 取り次ぐ先 |
|---|---|---|
| `#00_kei-agent` | Kei Agent 自身への要望 | オーケストレータ |
| `#01_overview` | 主にDailyとレトプラ | オーケストレータ → 各エージェント |
| `#02_research-strategy` | 中長期の方針 | オーケストレータ |
| `#10_<テーマ>` | そのテーマの研究作業 | 研究エージェント |
| `#20_course` | 授業と課題 | 大学エージェント |
| `#30_work` | 会社の予定・メール・資料 | 仕事エージェント |

- スレッドの外では `@Kei Agent` とメンションする必要がある
- Kei Agent が動いているスレッドの中では、メンションなしで利用可能

## 頼んだあとの見え方

- 受け取ると 👀、答え終わると ✅（エラーなら ⚠️）が依頼のメッセージに付く
- いま何をしているかは、入力欄の下の1行に出る
- Slack 本文には Kei Agent の結論だけが出る。途中の考え・手順・ツール名・ローカルパスは表示しない
- 数分以上かかりそうな作業は Kei Agent がジョブにし、終わると同じスレッドで会話を再開して報告する
- スレッドが長くなると [新しいスレッドで続ける] が出る。押すと引き継ぎメモを書いて新しいスレッドを立てる

## 研究

1. テーマごとに `#10_<テーマ>` のチャンネルを作り、Kei Agent を招待する
2. `~/research/<テーマ>/` と Notion の「テーマ」の行が自動でできる
3. `@Kei Agent 〜して` と頼む

- 添付したファイルは `inputs/` に入り、`outputs/` に新しくできたファイルはスレッドに添付される
- テーマの前提（研究分野、ジョブにする基準、文献の検索キーワード）は `~/research/<テーマ>/CLAUDE.md` に書く
- つなぎ先が要るときは、返事の最後に `🔒 接続: <ドメイン>（理由）` が出て、[許可する] [断る] のボタンになる

## 授業（`#20_course`）

- 「課題を取り込んで」… Moodle の締切を Notion の「課題」に入れる（履修している科目だけ）
- 「締切を教えて」… 近い順に、これから2週間ぶん
- 「今週どれくらいやった？」… Toggl の記録を科目ごとに集計する
- そのほかの質問… Box の学部要項と過去問、Notion の授業と課題を読んで、根拠の URL を付けて答える

締切は、朝のまとめと、24時間前の個別通知で届く。

## 仕事（`#30_work`）

- 「今日の予定は？」「今週の予定は？」… Outlook の会議
- そのほかの質問… メール・SharePoint・Teams・社内の人を探して答える

メールや資料の本文も、そのまま出す（このワークスペースは自分ひとりなので）。長いものは要約して、
必要なところだけを引用する。送信・予定の作成・削除はできない（読むだけ）。

## 定期実行

| 時刻 | 届くもの | 場所 |
|---|---|---|
| 07:00 | 先行研究の新着（`CLAUDE.md` の検索キーワードで探す。新着がなければ投稿しない） | テーマのチャンネル |
| 08:00 | 今日の予定（授業・会議・締切）を時刻の早い順に1本で。そのスレッドに Daily（今日のタスク／夜間処理の結果／確認待ち・期日・止まっているテーマ・返事待ち／今日考えるとよい問い） | `#01_overview` |
| 21:00 | Retro & Planning（今日の成果／未完了タスク）。最後に「夜間に実行したいタスクはありますか？」と聞く | `#01_overview` |
| 00:00 | 🌙 を付けた Task（一晩5件まで） | 元のスレッド |
| 22:00 | 保守（古いファイルの整理と `~/research/` のバックアップ） | — |

- メッセージに 🌙 のリアクションを付けると夜間に実行される。00:00 までに外せば実行されない

## 設定を変える（App Home）

- Slack で Kei Agent を開き、[ホーム] タブを開く
- 設定可能な変更は以下の通り

- テーマごとに許可した接続先（足す・外す）
- **声**の入/切（どちらも既定は切）
  - *知らせる* … 作業が終わったときなどに、机の上で声に出す
  - *聞く* … マイクを開けて話せるようにする。**切っている間はマイクを閉じる**。設定は再起動後も復元される
- 決まった時刻の処理の時刻とオン・オフ、その場で動かすボタン
- いま動いている依頼・ジョブ・返事待ち

同時に動かす数、上限時間、書き込み先、読ませない場所、基本の接続先は `config.toml`（柵）のままで、
Slack からは変えられない。

## 声で話す

`com.kei-agent.voice` が常駐している。**既定では何も喋らず、マイクも開けない。**
使うときは Slack の App Home で入れる。図は [voice.png](voice.png)、決めごとは [`voice.md`](voice.md)。

| App Home | 入れると |
|---|---|
| 知らせる | 作業が終わった・止まった・返事待ち・締切・上限を、通知時だけ接続して声で言う。マイクは開かない |
| 聞く | **OpenAI Realtime API に繋がって、普通に会話できる**。切ると繋がりごと切れる |

呼びかけは要りません。**繋がっているあいだは、そのまま話しかければ答えます**
（喋っている途中に割り込んでも止まります）。繋いでいる時間のうち、喋ったぶんだけお金がかかります。

| 聞くこと | 誰が答えるか | 待ち |
|---|---|---|
| 今日・明日・今週の予定、授業、会議、締切、Kei Agent の様子 | 手元に押してあるデータ | ほぼ0 |
| ふだんの会話、聞き返し | Realtime API | 会話のまま |
| 研究・授業・仕事の**中身** | 選択済み provider の担当 agent（「ちょっと見てみるね」と言ってから調べる） | 数秒 |

作業を頼むと、**渡す前に読み上げて確認します**。「amr-query に、〜、って頼むよ。いい？」に
「いいよ」と答えると Slack にスレッドが立ち、いつもどおり Kei Agent が作業します。

話した全文は `<agent_root>/overview/voice/<日付>.md` に残ります（30日で消える）。

机の上のロボット（Stack-chan）はまだ無いので、声は Mac のスピーカーから出ます。
